# 重建配方 —— WMPFDebugger（微信小程序逆向环境）

> 目标：在一台干净的 Windows 机器上，从零把这套工具装回可用状态。
> 一键脚本：`scripts\restore.ps1`（本文是它的手动展开与依据）。

## 1. 组件与来源

| 组件 | 来源 | 版本 / 体积 | 备注 |
|---|---|---|---|
| WMPFDebugger | `https://github.com/evi0s/WMPFDebugger` | `main` 分支，`--depth 1`，源码约 0.9 MB（含 12 MB 截图） | GPLv2 |
| Node.js | <https://nodejs.org> / 现有环境 | ≥ LTS v22（本机 v24.13.0） | |
| yarn | 由 **corepack** 提供 | 1.22.22（本机 corepack 自带解析） | 上游要求 yarn；**不要用 npm** |
| npm 依赖 | npm registry | `frida@17.3.2`、`protobufjs@7.5.4`、`ws@8.18.3`；dev：`ts-node@10.9.2`、`typescript@5.9.2`、`@types/node@24.5.2`、`@types/ws@8.18.1` | 由 `yarn.lock` 锁定，**勿删** |
| frida 预编译二进制 | GitHub release（由 frida 包的安装脚本拉取） | `node_modules\frida\build\frida_binding.node`，**115 MB** | **必须走代理**，否则超时 |
| 调试前端浏览器 | 系统已有 Chromium 系浏览器 | 不限；本机 Edge 143 实测可用 | **不要**为它装浏览器 |
| 微信（被调试端） | 官网 <https://pc.weixin.qq.com> | 4.x，WMPF 版本须在支持列表内（本机 16467） | |

安装后 `node_modules` 约 **148.5 MB**（几乎全是 frida 的二进制）。

## 2. 前置

- Windows + **pwsh 7**（脚本含中文，必须 UTF-8 with BOM 保存）。
- `node` ≥ 22、`corepack`（随 node）、`git`。
- 一个可用的 HTTP 代理（frida 二进制在 GitHub release）。本机为 Clash `http://127.0.0.1:7890`。
- 微信与本工具**同一用户权限**即可运行（本机普通权限实测通过）。

## 3. 分步命令

```powershell
# 0) 变量
$Root  = 'D:\AI_python\reverse\vmpfdebugger'
$Proxy = 'http://127.0.0.1:7890'

# 1) 克隆（浅克隆即可）
git clone --depth 1 https://github.com/evi0s/WMPFDebugger.git $Root
Set-Location $Root

# 2) 装依赖（代理是必须的）
$env:HTTP_PROXY  = $Proxy
$env:HTTPS_PROXY = $Proxy
$env:COREPACK_ENABLE_DOWNLOAD_PROMPT = '0'
corepack yarn install --frozen-lockfile --non-interactive

# 3) 落位两个启动脚本（来自本 skill 的 scripts\，是权威副本）
Copy-Item $DSH_HOME\skills\wmpf-miniapp-reverse\scripts\start-debugger.ps1 $Root -Force
Copy-Item $DSH_HOME\skills\wmpf-miniapp-reverse\scripts\open-devtools.ps1  $Root -Force

# 4) 校验
node node_modules\typescript\bin\tsc --noEmit          # 期望：无输出，exit 0
& .\node_modules\.bin\ts-node.cmd --version            # 期望：v10.9.2
node -e "require('frida').getLocalDevice().then(d=>console.log(d.name))"   # 期望：Local System
```

## 4. 验证（能力自检，不依赖微信）

| 检查 | 命令 | 期望 |
|---|---|---|
| 类型检查 | `node node_modules\typescript\bin\tsc --noEmit` | 无输出，exit 0 |
| frida 可用 | `node -e "require('frida').getLocalDevice().then(d=>console.log(d.name))"` | `Local System` |
| 进程识别 | 用 platform/win32.ts 的逻辑枚举 `WeChatAppEx.exe` | 枚举到 N 个进程，选出父进程 pid 并解析出版本号（本机曾得 11 个 / pid 2788 / 16467） |
| 浏览器前端 | 用一个假 CDP 服务端监听 62000，浏览器地址栏粘贴 `devtools://devtools/bundled/inspector.html?ws=127.0.0.1:62000` | 服务端收到 `Network.enable` / `Runtime.enable` 等握手（本机 Edge 143 实测通过） |

**实测过的完整链路**（2026-09-17）：启动脚本 → 重开小程序（`miniapp client connected`）→
粘贴链接（`cdp client connected`）→ DevTools 正常显示；用 `scripts\probe-cdp.js` 另开一个客户端
收到 797 条消息与持续 `Page.screencastFrame` 画面帧。

## 5. 关键事实与坑（重建时必须知道）

1. **`devtools://` 不能当命令行参数打开**：实测 Chrome for Testing 148 会忽略它并打开
   `chrome://newtab/`。**只能手工粘贴到地址栏**。这是 `open-devtools.ps1` 存在的原因。
2. **顺序**：启动调试器 → 重开小程序 → 打开前端。颠倒会让小程序闪退。
3. **首次打开 DevTools 可能空白**：前端在小程序连上之前发完初始化命令，命令被丢弃
   （代理只在有 miniapp 客户端时广播）。按 `F5` 刷新前端即可。
4. **别开全局代理/TUN**：会用 `Invalid WebSocket frame: invalid opcode 0` 弄崩小程序。
5. **不要用 npm 装**、**不要删 `yarn.lock`**（上游 FAQ 硬性要求）。
6. **用后台 job 跑调试器会留孤儿进程**：`job_kill` 杀掉包装进程后，`ts-node src/index.ts` 可能
   继续存活并占着 9421/62000。清理办法：
   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
     Where-Object { $_.CommandLine -match 'src[\\/]index\.ts' } |
     ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
   ```
   日常用前台窗口跑 + `Ctrl+C` 最干净（脚本有 SIGINT handler，会 detach Frida 并关服务）。
7. **沙箱与网络**：在受限沙箱下 `git clone` 会因无法创建管道报
   `cannot create standard input pipe for remote-https: Permission denied`，
   HTTPS 请求会报 `The SSL connection could not be established ... Authentication failed`。
   这不是网络问题，放宽沙箱即可（本机在 danger-full-access 下正常）。

## 6. 本 skill 目录的定位（自包含备份）

| 路径 | 内容 |
|---|---|
| `scripts\restore.ps1` | 一键重建（检查前置 → clone → 装依赖 → 落位脚本 → 校验 → 打印后续步骤） |
| `scripts\start-debugger.ps1` / `open-devtools.ps1` | 启动脚本权威副本（带 `-Root`，可从 skill 目录直接调用） |
| `scripts\probe-cdp.js` | CDP 链路排障探针 |
| `references\使用说明.md` | 详细说明书（流程 / 日志解读 / CDP 手法 / 排障） |
| `references\重建配方.md` | 本文件 |

**不备份**（都可重下）：

| 东西 | 体积 | 原因 |
|---|---|---|
| `node_modules\` | 148.5 MB | `yarn.lock` 锁定，一条命令可重装 |
| `screenshots\` | 约 12 MB | 上游仓库自带说明图，`git clone` 就有 |
| 整个工具目录 | — | 有 GitHub 来源，重 clone 即可 |

**永不备份**：无（这套工具不持有任何凭据；微信登录态在微信进程里，与本工具无关）。

## 7. 维护提醒

- 上游更新：`cd $Root; git pull`（浅克隆需 `git fetch --depth 1 && git reset --hard origin/main`）。
- 两个启动脚本有**两份**（`$Root\` 与 skill 的 `scripts\`）：改一处必须同步另一处，
  然后按 `skills-inventory` 的规则重新整份复制到 `local\skill\wmpf-miniapp-reverse\`
  并在 `SKILLS.md` 追加一行日志。
- 微信升级带来新 WMPF 版本时：先查 `frida\config\win32\addresses.<新版本>.json` 是否存在，
  不存在则按 `使用说明.md` 第 7 节处理。
- 升级 frida 版本时不要手改 `yarn.lock`，改 `package.json` 后重跑
  `corepack yarn install`（并挂代理）。
