# reverse-skill 包 · 重建与更新配方

本 skill（`reverse-skill-router`）是**自制的 DSH 适配层**：它本身只是一份说明书 + 一个重建脚本，
真正的内容是网络来源的仓库 `reverse-skill`。仓库不进 `local\` 备份，按下面的配方重装即可。

## 为什么不能平铺进 `$DSH_HOME\skills\`

仓库是个**路由包**：`skills\` 下 48 个模块互相用相对路径引用（`../ops/`、`../config/routing.json`、
`../CTF-Sandbox-Orchestrator/...`）。拆散或平铺会打断这些相对路径，也会把 89 个 skill 的自动加载面
一次放大。所以只注册**一个**入口 skill（本目录），仓库整包放在 `$DSH_HOME\reverse-skill`。

## 重建步骤

```powershell
$Proxy = $env:REVERSE_SKILL_PROXY      # 本机值见账本 INSTALL.md；留空则直连（本机直连会失败）
$Repo  = 'C:\Users\y\.dsh\reverse-skill'
$Pin   = '7e2097fd90d25c2f976f6eba26d6c00aa88051df'   # 审查过的 commit，不用 main 浮动版本

# 1) 按 pin 的 commit 克隆（浅克隆）
New-Item -ItemType Directory -Force -Path $Repo | Out-Null
git -C $Repo init -q
git -C $Repo remote add origin https://github.com/zhaoxuya520/reverse-skill.git
git -C $Repo -c http.proxy=$Proxy -c https.proxy=$Proxy fetch --depth 1 origin $Pin
git -C $Repo checkout -q FETCH_HEAD

# 2) 生成本机工具清单（gitignored，新克隆里不存在，缺了路由就没工具信息）
powershell -NoProfile -ExecutionPolicy Bypass -File "$Repo\skills\scripts\refresh-tool-index.ps1"

# 3) 路由自洽自检（应为 exit 0）
powershell -NoProfile -ExecutionPolicy Bypass -File "$Repo\skills\scripts\verify-routing-coherence.ps1"

# 4) 冒烟：随便给个任务串，应输出 PRIMARY -> skills/<模块>/SKILL.md
powershell -NoProfile -ExecutionPolicy Bypass -File "$Repo\skills\scripts\master-route.ps1" `
  -Hint "offline apk reverse jadx" -OutDir "$env:TEMP\rs-smoke"

# 5) 把本 skill 目录复制回 $DSH_HOME\skills\reverse-skill-router\（从 local\skill\reverse-skill-router\）
```

也可以用本目录的 `scripts\restore.ps1` 一次做完 1–4 步（已存在仓库时只做 2–4；`-Pull` 才更新）：

```powershell
$env:REVERSE_SKILL_PROXY = '<proxy-host>:<port>'
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.dsh\skills\reverse-skill-router\scripts\restore.ps1"
```

## 安全审查结论与红线（2026-09-15，skill-vetter 只读审查）

**结论：⚠️ 谨慎安装** —— 没有发现任何偷凭据 / 外发本机数据 / 混淆代码 / 绕过授权门禁的行为，
反而自带供应链自检（`verify-repository-security.py`：二进制哈希白名单、CI action pin SHA、
禁止 `Invoke-Expression`/`curl|sh`），工程质量高于同类包；但**上游是真实红队工具包**，装它等于
给 AI 完整红队能力，风险来自"能力 + 自动化倾向"，所以下列红线必须守：

审查提出的 **5 项加固**，本机落实情况：

1. 不平铺 89 个 `SKILL.md` —— ✅ 已按薄适配层形态安装；
2. "bootstrap / quick-setup / install-autostart 一律先问用户"写成硬约束 —— ✅ 已写进 `SKILL.md` 硬规则表格；
3. 代理参数化（`-Proxy` / `REVERSE_SKILL_PROXY`）、`SKILL.md` 不再出现内网 IP、克隆按审查过的 commit pin —— ✅；
4. `update-star-history.ps1`（`git credential fill` 读本机 GitHub token 外发）列入**永不执行** —— ✅；
5. `install-autostart.ps1` 列入**永不执行**，并给出启用 `ida-reverse` 前对 `start.ps1` 的两处硬化 —— ✅
   （方案见下节；仓库文件本身**未改**，保持与上游一致以便 `git pull`）。

补充事实（审查已核实，用于下次核对）：本仓**无** `curl|bash`、无混淆 / `eval`、无窃取 `~/.ssh` / `~/.aws` /
浏览器 cookie / DSH token、无提示注入语料、无"关杀软"要求；Burp 桥与 MCP 服务端只绑 `127.0.0.1` 且强制
Bearer 鉴权、全仓无 `Runtime.exec` / `ProcessBuilder`；Kali 安装器对 GitHub Release 资产强制 SHA-256、
缺校验值即 fail-closed；`CTF-Sandbox-Orchestrator/` 0 可执行代码；两个 PNG 均以 `IEND` 正常结束（非 polyglot）。
唯一未核实项：`gradle-wrapper.jar` 的 SHA256 与仓库自检白名单一致，但有说法称它对应 Gradle 8.10–8.12 而
`gradle-wrapper.properties` pin 的是 8.7 —— 标为"待上游确认"，**不是已确认的篡改**。

| 脚本 | 危险动作 | 策略 |
|---|---|---|
| `skills\scripts\update-star-history.ps1` | `git credential fill` 读本机 GitHub token，Bearer 外发到 api.github.com | **永不执行** |
| `skills\ida-reverse\scripts\install-autostart.ps1` | 注册隐藏计划任务：**每分钟**、3650 天、`Hidden`；链条 `install-autostart.ps1` → `watchdog.ps1`（服务不在就无条件启）→ `start.ps1`（缺 `idalib-mcp` 就**无人值守**跑 `bootstrap-reverse.ps1 -Capability idalib-mcp` → `pip install git+https://github.com/mrexodia/ida-pro-mcp.git@f82e6e25…`），并以 `--unsafe` 启动（对 `127.0.0.1:13337` 暴露 `py_eval` / `py_exec_file`） | **永不执行**（详见下节硬化说明） |
| `kali\scripts\quick-setup.sh` 等 | `sudo apt-get update && apt-get upgrade`（全系统升级）、覆写 MCP 配置 | 本机 Windows，**不执行** |
| `skills\scripts\bootstrap-reverse.ps1` / `.sh` | winget / `npm -g` / `pip` / `go` / `git clone` **真装工具链**，写 `%USERPROFILE%\Tools\`、用户级环境变量、MCP 注册 | **先问用户**才可跑 |

仓库内容层面的注意事项（不是恶意，是"真实攻击资料"）：

- `skills\pentest-tools\src-hunter\references\payloader\`、`playbooks\rce.md` 等含 webshell / 反弹 shell
  载荷文本（约 72 文件 / 3.5 MB），本地杀软可能告警 —— 上游 `SECURITY.md` 明确说**不要为此关闭防护**；
- `reports\` 里有一份**未脱敏的第三方 pentest 报告**（真实域名 + PoC），视为第三方隐私，不要外传；
- `edr-bypass-re/`、`attack-chain/` 等模块只有"授权后使用"的软措辞，实际门禁靠 `case-init`/`case-guard`，

- 仓库根的 `AGENTS.md` / `CLAUDE.md` 会被部分宿主自动加载（本机仓库不在工作区，DSH 不会自动加载它们）。

## 若要用 IDA MCP（`ida-reverse`）：先做两处硬化

本机现状：`ida` / `idalib-mcp` / `ida-pro-mcp` 全部缺失，**没有注册过**任何计划任务，风险链处于未激活状态。
哪天确实要让 IDA MCP 常驻，先改仓库里这两个文件（改完在账本追加日志，更新后 git pull 会冲突，需要重做）：

1. `skills\ida-reverse\scripts\start.ps1:389-397` —— 删掉/注释掉那段"缺 `idalib-mcp` 就自动调用
   `bootstrap-reverse.ps1 -Capability idalib-mcp -SkipRefresh`"的 auto-bootstrap，改为**打印缺失提示并退出**，
   让安装动作回到"用户显式同意"。
2. `skills\ida-reverse\scripts\start.ps1:404`、`:420-421` —— 去掉固定传入的 `--unsafe`
   （上游注释自承它 exposes `py_eval` / `py_exec_file`，等于给 `127.0.0.1:13337` 一个任意 Python 执行面）。
   需要脚本化操作 IDA 时再按需临时开启，用完关掉。
3. 不要跑 `skills\ida-reverse\scripts\install-autostart.ps1`（它是上面那条每分钟自动装码链的入口）；
   要常驻就用前台手动启动。

## 目录约束（搬家时必须整包搬）

- `CTF-Sandbox-Orchestrator\` 必须与 `skills\` **同级**（`skills\routing.md` 里 `../CTF-Sandbox-Orchestrator/...` 依赖此结构）。
- `skills\tool-index.md` / `tool-index.json` 是本机生成物，**不备份、不复制**，到新机器重跑 refresh。
- 包根用 `RULES.md` 定位，别写死盘符。

- 任何 MCP / 客户端配置（仓库本身不写客户端全局配置；本机也没有为它写过）
