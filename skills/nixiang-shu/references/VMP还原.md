## 阶段：侦察

<a id="vmp-001"></a>
#### vmp-001 先分壳/混淆/VMP/白盒四类再决定是否还原
- 症状：不确定是不是VMP；看不懂 so 入口
- 判断：so 能直接进 IDA 正常反编译 → 不是 VMP；for(;;)+大 switch+[++[]] → JSVMP；0x8000C000 初值且每轮 +4 → 原生栈式 VM
- 动作：十分钟定性，先排除加固与白盒；定性错则后续锚定、切 handler 全白做
- 无效则：三类特征都不齐 → 按自研 VM 处理，用最简样本探分派形态
- 失效条件：自研 VM 用函数指针表分派、没有 switch 时上述三连特征全部不出现
- 证据：strong ｜ 3源(52pj3) ｜ 2025–2026 ｜ 命中22
- 锚点：2016248,2116112,2005863

<a id="vmp-002"></a>
#### vmp-002 先判实现类型与版本再选方法，不套固定脚本
- 症状：照教程做完全失效；换样本脚本无效
- 判断：VMProtect 看 VMProtectBegin 桩；Themida 看驱动层；JSVMP 看 JS；自研看分派形态。版本>家族
- 动作：记录版本→查该版本特征是否仍成立→只用不依赖版本的手段：trace、handler 模板
- 无效则：版本查不到 → 当自研 VM，禁一切特征码与现成脱壳/还原脚本
- 失效条件：VMProtect 3.8 起一个 handler 承载多原语，特征识别语义不全；3.9.4 加内存操作数常量隐藏
- 证据：strong ｜ 3源(52pj3) ｜ 2025–2026 ｜ 命中10
- 锚点：2088542,2101175,2005863

<a id="vmp-003"></a>
#### vmp-003 能 dump 就别还原，先算还原收益
- 症状：还原很久只为拿一次结果；结果只在运行时有效
- 判断：同一版本内不变的值/算法 → dump 或运行期取结果比还原便宜；只有必须改的语义才值得还原
- 动作：先试内存 dump、hook 取返回值；静默失效（不报错但结果错）同样算此路不通
- 无效则：值随设备/时间变（混入 TracerPid、时间、签名）→ dump 无效，必须还原
- 失效条件：目标对 dump 结果做 Loader 回写或自校验时，dump 只解决静态可比对
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2026 ｜ 命中33
- 锚点：1512064,2126459,1243722

<a id="vmp-004"></a>
#### vmp-004 找不到 .init_array 是节头被抹，看 LOAD 段
- 症状：IDA 没有具名节；init_array 找不到　报错：`Section header not found`
- 判断：IDA 无具名节 → Section Stripped；在 LOAD 数据段搜 19 00 00 00（DT_INIT_ARRAY=25）
- 动作：按 dynamic tag 定位 init_array；静态锚点废就转内存与 trace
- 无效则：mmap 模块化（运行期解密+匿名映射）→ 在 mprotect 回调按 base_size_idx 存盘
- 失效条件：节头被伪造（假名假大小）时先比对节区与内存映射
- 证据：weak ｜ 2源(52pj2) ｜ 2025–2025 ｜ 命中4
- 锚点：2077394,2029498

<a id="vmp-005"></a>
#### vmp-005 认出标准常量表就调库，别逆压缩函数
- 症状：怀疑自研加密；hash 对不上
- 判断：0x67452301 家族→MD5/SHA-1；0xC3D2E1F0→SHA-1 K；0xedb88320→CRC32；内存 0x36 重复=ipad、0x5C=opad→HMAC
- 动作：先按常量表认算法，不认识的那段才写 handler 语义；40 位 hex+64 字节块+80 轮 → SHA-1
- 无效则：常量表缺失或位置被挪 → 判魔改，按 trace 重写
- 失效条件：常量运行期生成/加密时，静态搜常量表不再命中
- 证据：strong ｜ 3源(52pj3) ｜ 2025–2026 ｜ 命中13
- 锚点：2116112,2073893,2007041

<a id="vmp-024"></a>
#### vmp-024 反混淆不求全：先统计变体，只处理模板化那种
- 症状：反混淆脚本越写越大；永远收不了尾
- 判断：变体有限且模板化 → 值得写通用变换；无穷变体 → 脚本永远收不了尾
- 动作：按 handler 指纹聚类统计变体数，只处理占比最高那种，剩下绕过或硬读
- 无效则：变体太多 → 转黑盒：只恢复 CFG 或运行期取结果
- 失效条件：样本按实例随机化 handler 排列时聚类失效，指纹需按语义而非字节
- 证据：weak ｜ 2源(52pj2) ｜ 2023–2026 ｜ 命中121
- 锚点：1792058,2088542

## 阶段：定位

<a id="vmp-006"></a>
#### vmp-006 so 无 Java_ 导出就抓动态注册表
- 症状：so 搜不到 Java_ 函数；native 声明找不到实现
- 判断：导出表无 Java_* 而 Java 侧有 native → 动态注册；步长 3*pointerSize
- 动作：hook RegisterNatives，一次拿 class/name/sig/base/offset 再算地址
- 无效则：注册表被加密或延时注册 → 在调用点回边 hook 或扫 .data.rel.ro 指针
- 失效条件：结构体/代理式注册时 3*pointerSize 步长不成立
- 证据：weak ｜ 2源(52pj2) ｜ 2020–2025 ｜ 命中144
- 锚点：1243722,2065441

<a id="vmp-007"></a>
#### vmp-007 用唯一自执行函数定位 JSVMP 解释器入口
- 症状：JS 里找不到加密入口；整站 JS 只有一个巨型函数
- 判断：格式化后只有一个自执行函数、业务函数都是被动调用 → 那个自执行函数就是 VM 入口
- 动作：格式化全文，搜 (function(){})() 与 new Function，再用 apply/.call 出现位置交叉确认
- 无效则：多个自执行候选 → 按调用栈深度与阻塞时长排序，取被业务直接调的那个
- 失效条件：解释器改为 chunk 懒加载（webpack 动态 import）后，入口不再自执行
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中4
- 锚点：2084662,2123850

<a id="vmp-010"></a>
#### vmp-010 先判栈式还是寄存器式，再建解释器模型
- 症状：按教程建的解释器对不上；操作数取值一直错
- 判断：函数开头声明 v0,v1,v2… → 寄存器式；只有一个 h 数组+p 当 PC+g 当返回栈 → 栈式
- 动作：栈式按 h/p/g 三变量建模，寄存器式按 v 数组建模；模型错则 opcode 语义永远对不上
- 无效则：混合模型 → 以数据真实落点（谁被 STR/LDR）为准，不硬套两类模板
- 失效条件：自研 VM 用结构体 ctx 承载全部状态时，变量声明形态不暴露模型
- 证据：weak ｜ 2源(52pj2) ｜ 2025–2026 ｜ 命中8
- 锚点：2116112,2005863

<a id="vmp-011"></a>
#### vmp-011 用最简样本推 opcode 位域并验定长
- 症状：opcode 与操作数分不开；字节码切分差一
- 判断：同一 opcode 在不同输入下位段不变 → 位段是编码；值变的是操作数
- 动作：三步：读 switch 得 opcode 集合→最小输入跑 trace 记 opcode/操作数/栈变化→按位段分组验；定长式与 trace IP 对拍
- 无效则：定长对不上 → 按变长处理，用 IP 增量直方图反推编码
- 失效条件：3.8 起一个 handler 承载多原语，opcode 与语义不再一一对应；0x30 是样本特定值
- 证据：strong ｜ 3源(52pj3) ｜ 2025–2026 ｜ 命中118
- 锚点：2007041,2005863,2127122

<a id="vmp-014"></a>
#### vmp-014 trace 范围宁小勿大，限在模块 base~base+size
- 症状：trace 一开就卡死；日志文件几百 MB　报错：`exception in thread`；`OutOfMemory`
- 判断：不传 end 即 trace 整个 so，单 case 可打 400MB 把自己卡死
- 动作：只开模块区间或函数区间；先挂 CodeHook 计数，按 40 万行/分钟估时间
- 无效则：区间模糊 → 先 traceWrite 定位写点，再收窄到那个函数
- 失效条件：JIT/自解密把代码搬到匿名映射后，模块区间不再覆盖实际执行区
- 证据：strong ｜ 3源(52pj3) ｜ 2023–2026 ｜ 命中14
- 锚点：2116795,1743632,2090538

<a id="vmp-016"></a>
#### vmp-016 自修改/JIT 样本别用 Stalker，它会锁死第一版指令
- 症状：同一地址改了却没生效；只执行旧指令
- 判断：同一地址反复改写却只执行第一版 → Stalker.follow 的地址缓存+快照时机 bug，是工具问题不是目标逻辑
- 动作：换 QBDI 或自造最小靶子复现；必须用 Stalker 时限定范围并在关键点 unfollow/refollow
- 无效则：换工具仍锁死 → 目标自身有代码缓存，去查它的解密与刷新时机
- 失效条件：frida 修掉该缓存 bug 后锁死现象消失，此判断只对受影响版本成立
- 证据：weak ｜ 2源(52pj2/kanxue0) ｜ 2025–2026 ｜ 命中3
- 锚点：2021050,2116795

<a id="vmp-017"></a>
#### vmp-017 JS 插桩三轮递进：apply→运算符→全局栈
- 症状：日志太多看不出主线；不知插什么
- 判断：只插 apply 就能看出函数边界 → 停；不够再插运算符；再不够才建全局栈
- 动作：一轮只 hook apply/.call；二轮用 new Function 拼运算符；三轮才建全局栈；探针先执行再记录
- 无效则：元操作被别名化或内联 → 改走 AST 插桩 AssignmentExpression+MemberExpression(.call())
- 失效条件：解释器改用 Proxy/Reflect 白名单化元操作后，apply 点位消失
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中16
- 锚点：2098573,2123850

<a id="vmp-018"></a>
#### vmp-018 日志必须带自增调用 id 并落数组落盘
- 症状：日志撒了一地也没看懂；控制台滚动条滚不完
- 判断：日志没有编号就无法排序、也看不出函数边界 → 控制流还原不了
- 动作：打 CALL_/BIN_/RET_ 前缀+序号，写 window.__LOGS__ 再导出；含不可见字符要先落盘再读
- 无效则：日志撑爆内存 → 按 id 分段 flush 落盘
- 失效条件：页面有日志长度/频率检测时，全量日志会直接触发风控
- 证据：weak ｜ 2源(52pj2) ｜ 2025–2026 ｜ 命中4
- 锚点：2106666,2079071

## 阶段：校验

<a id="vmp-020"></a>
#### vmp-020 结构像但常量不符就是魔改，写反变换别重写算法
- 症状：文档说是 HMAC-SHA1 但算不对；结构和标准算法一模一样
- 判断：轮结构/分组长度都对得上，但常量不是标准 magic 或注入位置被挪 → 魔改
- 动作：逐项对三处高发点：初始常量、K 值分段边界、末轮变量赋值顺序；只写反变换
- 无效则：差异超过三处 → 按 trace 重建算法，别找现成实现
- 失效条件：接口文档声称标准算法而实测不符时以实测为准，文档提示不等于实现
- 证据：strong ｜ 3源(52pj3) ｜ 2021–2026 ｜ 命中7
- 锚点：1537069,2107248,2070588

<a id="vmp-021"></a>
#### vmp-021 MBA 堆叠先化简，符号扩展单列清单
- 症状：表达式一堆位运算看不懂；一处错导致全盘皆错
- 判断：~ ^ | 堆叠且只依赖少数变量 → MBA 指令替换非加密；出现 SXTB/SXTH 或 arg==7 这类边界编码 → 一处符号扩展错全盘错
- 动作：先按语义化简（v ^ -476 多半就是常量 1）再读；把符号扩展与边界常量列清单逐条在 trace 上验
- 无效则：化简后仍复杂 → 用求解器做等价验证，别继续手推
- 失效条件：MBA 与真实非线性（魔改 S 盒）混排时纯化简会抹掉真实逻辑；编码改变长后符号扩展点随 opcode 变
- 证据：weak ｜ 2源(52pj2) ｜ 2025–2025 ｜ 命中14
- 锚点：2005850,2052174

<a id="vmp-022"></a>
#### vmp-022 提升 IR 时值一律取自 trace，绝不自己算
- 症状：IR 里的值对不上；折叠后结果偏移
- 判断：自己推出来的中间值，与 trace 对不上时分不清是模型错还是算错
- 动作：varnode 折叠只替值不造值；两代 IR 交叉验证，任一值与 trace 不符即回退
- 无效则：trace 缺该点 → 补插桩，不许用推算填洞
- 失效条件：trace 本身改变执行路径（见无日志对照）时，trace 值不能当基准
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中157
- 锚点：2127122,2084662

## 阶段：验证

<a id="vmp-015"></a>
#### vmp-015 先做无日志对照，确认 trace 不改变行为
- 症状：开了 trace 结果就变了；装上 hook 就起不来
- 判断：开 trace 后返回值/分支/时序变了 → trace 干预了启动流程，后续结论全错
- 动作：同输入跑无 hook 基线与带 trace 两遍，比对返回值与关键分支；不一致就降粒度或换工具
- 无效则：关掉也复现不了 → 结论降级为推断，另找不依赖 trace 的证据
- 失效条件：目标用时间差/计数器反调试时，任何插桩都改时序，干净基线不可得
- 证据：weak ｜ 2源(52pj2) ｜ 2025–2026 ｜ 命中10
- 锚点：2090538,2021050

<a id="vmp-026"></a>
#### vmp-026 双向验证：还原算法重加密要对上目标密文
- 症状：本地值算对了但线上不通；重放就失败
- 判断：本地值与抓包一致只是必要条件；能把明文重新加密出同一密文才算充分
- 动作：用真实输入输出双向跑，再用代理重放真实请求对账
- 无效则：只有单向（拿不到明文）→ 用多组输入输出做一致性覆盖
- 失效条件：密文含时间戳/随机数时重放对不上是正常的，需先固定随机源
- 证据：weak ｜ 2源(52pj2) ｜ 2021–2021 ｜ 命中7
- 锚点：1537069,1512064

<a id="vmp-027"></a>
#### vmp-027 反混淆脚本要覆盖回原程序跑稳定性校验
- 症状：在自己挑的样本上对；换个入口就不对
- 判断：脚本只在自己挑的样本上对 → 未覆盖的分支仍是错的
- 动作：把结果覆盖回原程序，多入口多输入各跑一次看是否仍等价
- 无效则：原程序不可跑 → 用 trace 覆盖率（命中 handler 数/总数）代替
- 失效条件：程序带自校验（文件被改即失败）时，覆盖前得先绕过自校验，否则测不出等价性
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中4
- 锚点：2088542,2107248
