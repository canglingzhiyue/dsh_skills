## 阶段：侦察

<a id="websec-001"></a>
#### websec-001 先删签名重放，再决定要不要还原算法
- 症状：sign 参数看不懂不敢动；不知道要不要逆签名；签名可能根本没用
- 判断：删掉或改错 sign 重放仍返回业务数据 → 服务端不校验该签名，整条签名逆向链可以直接省掉
- 动作：Repeater/Composer 里先把 sign 删掉发一次，再改成错值发一次，看响应是否仍落业务分支
- 无效则：返回 401 或「签名无效」→ 转 websec-007 还原签名
- 失效条件：接口改成全字段强校验签名、删任一参数即 401 后，这条捷径关闭（多见于支付/提现类接口）
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2022 ｜ 命中6
- 锚点：1121936,1496965,1702953

<a id="websec-002"></a>
#### websec-002 同操作连抓两次做字段 diff，先圈出校验量
- 症状：参数太多不知从哪下手；看不出哪个字段是校验值
- 判断：两次请求逐字段对比后只有 signature/nonce/timestamp 变 → 这三项是动态校验量，其余业务参数可枚举
- 动作：同一操作连抓 2–3 次，逐字段对比，只保留发生变化的字段作为逆向目标
- 无效则：全字段都不变 → 该接口无动态校验量，直接进重放实验（websec-004）
- 失效条件：接口把业务参数整体加密进一个 body 字段后，diff 出的校验量其实是整段密文，不再是单项
- 证据：weak ｜ 2源(52pj2) ｜ 2019–2021 ｜ 命中7
- 锚点：1006989,1396008

<a id="websec-004"></a>
#### websec-004 先给接口防护强度分三档再决定投入
- 症状：不知道该花多少力气；sign 是否一定要还原；怕白做整条签名链
- 判断：replay/modify/delete 三组实验把接口分到无防护、伪随机可复现、强绑定三档，档位决定要不要动 native
- 动作：三组实验各发一次并记录响应码；能过 delete 就不碰签名，只能过 replay 才值得进 so
- 无效则：三组全被拒说明强绑定 → 转 hook 取真值，不做离线构造
- 失效条件：服务端按账号灰度风控策略（同接口 A 号放行 B 号拒绝）时，单账号三档结论不能外推
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2022 ｜ 命中1
- 锚点：1702953,1121936,1496965

<a id="websec-012"></a>
#### websec-012 重签名后全网断连即服务端校验签名
- 症状：改包后无法联网；重签名功能全消失；改包后一直网络错误　报错：`网络连接失败`；`network error`
- 判断：原包正常、改包后所有请求都失败 → 服务端校验包签名，本地改判定全部无效，唯一出路是伪造上传的签名串
- 动作：对比原包与改包的同一接口响应，确认失败点在首个业务请求还是握手层
- 无效则：只有部分接口失败 → 是样本自己的签名自校验，回头查证书遍历
- 失效条件：改包时保留了服务端校验所需的签名字段（伪造上传串）后，断连现象消失，此判据不再能定性
- 证据：weak＋缺口 ｜ 3源(52pj3) ｜ 2016–2022 ｜ 命中10
- 锚点：561035,1137911,1726300　依据在图中，未复核

<a id="websec-013"></a>
#### websec-013 模拟器专属失败先怀疑环境指纹
- 症状：模拟器上功能降级；真机正常模拟器不行　报错：`device_register 返回降级标识`
- 判断：失败集中在设备注册类接口、且同一账号换真机即正常 → 环境指纹被判，往「改 App 逻辑」找是白费
- 动作：抓设备注册接口，用真机成功响应顶替模拟器响应（AutoResponder），再看业务接口是否放行
- 无效则：顶替后仍降级 → 查该标识是否被并入后续签名或风控字段
- 失效条件：服务端把指纹结果并入交易级风控后，只顶替注册响应不再放行后续交易
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中41
- 锚点：2121760,2121592

<a id="websec-015"></a>
#### websec-015 对象 ID 明文放 GET 的接口先测水平越权
- 症状：接口带 UserID 参数；参数是连号　报错：`403`；`无权限`
- 判断：把 UserID/uid 换成相邻连号仍成功 → 服务端不校验请求者与对象归属，属水平越权 IDOR
- 动作：用自己两个账号各取一次响应，交叉替换 ID 重放，看是否互相读到数据
- 无效则：改 ID 被拒 → 改测导出组件/跳过前置界面（websec-017）
- 失效条件：接口加上归属校验（uid 绑进 token 且服务端按 token 取对象）后，改 ID 一律被拒
- 证据：weak＋缺口 ｜ 2源(52pj2) ｜ 2022–2022 ｜ 命中57
- 锚点：1642498,1618599　依据在图中，未复核

## 阶段：定位

<a id="websec-003"></a>
#### websec-003 签名定位按命中数选关键词，别搜 sign
- 症状：搜 sign 几百条结果；定位不到签名代码
- 判断：sign/signature 泛滥，nonce/randomStr 常只有 1 命中 → 命中最少处即签名拼装代码
- 动作：依次搜 sign、nonce、randomStr，按命中数排序，从最少处切入
- 无效则：都搜不到 → 改搜 System.loadLibrary / WebAssembly.instantiate
- 失效条件：字段名混淆成 a/b/c 且字符串数组化后关键字失效，改按调用栈回溯
- 证据：strong ｜ 3源(52pj3) ｜ 2019–2021 ｜ 命中12
- 锚点：1006989,1396008,1388335

<a id="websec-019"></a>
#### websec-019 签名不是纯函数就放弃硬编码复用
- 症状：抓到的签名复用被拒；同样输入结果不同；存一个值反复用　报错：`签名错误`；`invalid sign`
- 判断：同一入参两次算出不同值且两个值都能过 → 算法吃了随机数或内存地址，固定值复用必然被拒
- 动作：连调两次比对输出；确认非确定后改为 hook 生成函数直接取返回值
- 无效则：输出稳定但复算对不上 → 查随机段（uuid/nonce）是否参与（websec-020）
- 失效条件：算法改为确定性实现（去掉地址/随机参与）后，可按公式离线复算
- 证据：weak ｜ 2源(52pj2) ｜ 2021–2022 ｜ 命中2
- 锚点：1610506,1497831

<a id="websec-022"></a>
#### websec-022 常见签名骨架：排序→编码→拼盐→摘要
- 症状：签名算出来对不上；参数一致但 sign 不同　报错：`invalid sign`
- 判断：签名里含时间戳且能离线复算 → 多为「参数排序 + URL 编码 + & 连接 + 拼盐 + 摘要」骨架，先套骨架再抠差异
- 动作：按骨架复算一次，与抓包值逐字符对比，差异只可能出在大小写、空值处理、盐位置
- 无效则：骨架对不上 → 查是否含空值参数、是否 HMAC 而非纯摘要
- 失效条件：签名改用 HMAC 且密钥服务端下发、或改非对称签名后，离线复算不成立
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2021 ｜ 命中22
- 锚点：1315172,1377608,1476924

<a id="websec-023"></a>
#### websec-023 用删参重放做控制变量定签名字段集
- 症状：不知道哪些参数进签名；签名字段要一个个试　报错：`签名错误`
- 判断：删一个参数发一次，被拒说明它参与签名 → 不读代码就能把参与集合列全，比读拼装代码快且结论更硬
- 动作：对每个可疑参数单独删除后重放，记录哪几个导致拒绝，得到参与集合
- 无效则：全删都通过 → 签名未覆盖参数，判据失效，改用请求 diff
- 失效条件：服务端对缺参返回默认值而非拒绝时，删参实验得不出参与集合
- 证据：weak ｜ 2源(52pj2) ｜ 2019–2021 ｜ 命中7
- 锚点：1476924,1006989

## 阶段：校验

<a id="websec-005"></a>
#### websec-005 判签名是否绑时间戳或一次性 nonce
- 症状：旧包重放报签名错；改完参数就提示过期　报错：`认证过期`；`invalid signature`
- 判断：同一包隔几分钟再发仍成功 → 无时效窗口；回「认证过期 / invalid signature」→ 签名绑了时间窗口或一次性 nonce
- 动作：同一请求隔 1 分钟与 10 分钟各重放一次，比响应码
- 无效则：有窗口但不影响重放节奏 → 只复算时间项，不必还原整链
- 失效条件：服务端把窗口收窄到秒级并校验时间来源（服务端下发 created）后，本地造时间戳也失效
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2021 ｜ 命中22
- 锚点：1547120,1315172,1332545

<a id="websec-006"></a>
#### websec-006 把客户端身份校验和业务签名分开判
- 症状：改了参数就被拒；提示客户端身份校验失败　报错：`"errno":-105`；`客户端身份校验失败`
- 判断：报错是客户端身份校验失败、且改任何业务参数都被拒 → 该字段绑设备/环境而非业务参数，凑参数没用
- 动作：逐个替换设备型字段（imei/macaddr/uuid）重放，观察是否必须三者自洽才放行
- 无效则：三项自洽仍拒 → hook 该值生成函数取真值，不手工拼造
- 失效条件：服务端把身份校验降级为只记录不拦截后，这条不再能靠拒绝现象区分两类校验
- 证据：weak ｜ 2源(52pj2) ｜ 2021–2021 ｜ 命中5
- 锚点：1370540,1351606

<a id="websec-007"></a>
#### websec-007 改参数被拒先查有没有同步重算签名
- 症状：改 page 后签名错误；改一个字段就失败　报错：`签名错误`
- 判断：signature 覆盖整个参数集合，改任一字段不重算必失败；重算仍拒说明还有第二道签名函数
- 动作：回到拼装处确认参与字段与拼接顺序，改值后整体重算再发；仍拒则搜第二个签（如 Util.b(Map)）
- 无效则：找不到第二道签名 → 用删参重放定位它覆盖的字段（websec-023）
- 失效条件：签名改为服务端下发的一次性 token 后，本地重算不再可行，只能重放真 token
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2020 ｜ 命中10
- 锚点：1149036,1336835,1137911

<a id="websec-008"></a>
#### websec-008 重放失败先找被绑定的那个变量
- 症状：原包重放领不到；重放没反应；以为没漏洞
- 判断：同包重放失败但换对象 ID/券码后成功 → 绑定的是对象归属或幂等键，不是签名，方向不该换成逆算法
- 动作：换一个自己账号名下的同类对象 ID 重放一次，看是否返回成功
- 无效则：换 ID 仍失败 → 回到签名/时效链（websec-005、007）
- 失效条件：服务端加了「请求者-对象」归属校验与幂等表后，换 ID 亦被拒，此判据失效
- 证据：weak ｜ 2源(52pj2) ｜ 2020–2021 ｜ 命中1
- 锚点：1569454,1186507

<a id="websec-010"></a>
#### websec-010 改失败响应看客户端是否买账
- 症状：界面提示失败但接口没报错；不知道判定在不在本地　报错：`isblock`；`errorcode`
- 判断：手改 errorcode/响应字段后客户端放行 → 判定在客户端；改完毫无变化 → 服务端判决，改本地无效
- 动作：抓一次失败响应，用拦截器改写后注入客户端，观察被锁功能是否解锁
- 无效则：客户端无反应 → 转查服务端实际下发内容与后续请求
- 失效条件：客户端加了响应签名/HMAC 校验后，改过的响应被直接丢弃，此法失效
- 证据：weak ｜ 2源(52pj2) ｜ 2021–2022 ｜ 命中1
- 锚点：1610120,1378626

<a id="websec-017"></a>
#### websec-017 UI 置灰不是防护，直接打接口验证
- 症状：按钮点不了；以为没入口就放弃了　报错：`401`；`403`
- 判断：界面禁用但接口没有对应校验 → 限制只在前端；绕过 UI 直接构造请求即可验证可信边界在哪
- 动作：从抓包复制该功能请求，改需要的参数后在 Repeater/Postman 重放，全程不经过界面
- 无效则：接口同样拒绝 → 限制在服务端，按签名/角色链处理
- 失效条件：前端禁用的同时服务端按角色鉴权后，绕过 UI 直接打接口也被拒
- 证据：weak＋缺口 ｜ 2源(52pj2) ｜ 2022–2022 ｜ 命中7
- 锚点：1618599,1642498　依据在图中，未复核

<a id="websec-027"></a>
#### websec-027 交易级风控只能记录不能伪造
- 症状：本地都过了一切仍被拒；交易还是失败　报错：`风控拦截`；`交易失败`
- 判断：本地检测过、节点降暴露也做了而交易仍失败 → 判定在服务端，客户端已无可改的判定点
- 动作：分三层各测一遍：本地检查、节点降暴露、交易级 verdict，逐层记录是否通过
- 无效则：确认是交易级 → 只做如实记录，不再往客户端找判定点
- 失效条件：服务端把交易级 verdict 下推到客户端 SDK 并本地拦截后，这条边界前移
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中31
- 锚点：2121760,2121592

## 阶段：验证

<a id="websec-009"></a>
#### websec-009 重复十次成功才证明缺幂等
- 症状：一次成功就写结论；怀疑无幂等但证明不了　报错：`429`；`Too Many Requests`
- 判断：同一请求连发 10 次都成功且业务计数递增 → 缺幂等（状态机缺陷），一次成功只能说明当时没拦
- 动作：固定间隔重放 10 次，逐次记录响应与业务计数；出现限流就降到低频并记阈值
- 无效则：第 2 次即失败 → 是幂等键或归属绑定，不是可重复利用的缺陷
- 失效条件：服务端接入幂等键或按账号频控（3 次后 429）后，重复成功不再成立
- 证据：weak＋缺口 ｜ 2源(52pj2) ｜ 2020–2021 ｜ 命中16
- 锚点：1569454,1186507　依据在图中，未复核

<a id="websec-028"></a>
#### websec-028 验收看服务端错误码，不看界面状态
- 症状：界面显示会员了算不算成功；UI 变了但功能没通　报错：`invalid sign`；`账户不存在`；`密码错误`
- 判断：「账户不存在/密码错误」= 加密与签名已过、进入业务校验；「签名错误/invalid sign」= 还没过。界面变化永远不是证据
- 动作：用被锁的实际功能做端到端验证，同时记录响应码与业务字段两项证据
- 无效则：只有界面变化 → 回退，按 websec-010 判客户端/服务端
- 失效条件：服务端把错误码统一成一句通用提示后，错误码不再能区分卡在哪一层
- 证据：weak ｜ 2源(52pj2) ｜ 2016–2023 ｜ 命中5
- 锚点：1803699,561035
