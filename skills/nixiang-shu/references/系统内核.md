## 阶段：侦察

<a id="neihe-001"></a>
#### neihe-001 先判内核版本与修复边界，再选漏洞路线
- 症状：照抄公开 exp 跑不通；怀疑复现环境版本不对；崩点与帖子不一致
- 判断：目标版本 ≥ 修复版本（该 UAF 在 v6.0.3 修）→ 漏洞已消失，调参数无意义
- 动作：先读 uname -r 与 /proc/version 定版本，查该 CVE 的 fixed-in 提交，复现环境选修复前内核（实测用 v5.18.19）
- 无效则：不能换内核 → 换配置/逻辑型弱点或另一条 CVE
- 失效条件：漏洞属配置或逻辑错（不随版本修复）时，版本判别不决定成败
- 证据：weak ｜ 2源(kanxue2) ｜ — ｜ 命中2
- 锚点：285909,283073

<a id="neihe-002"></a>
#### neihe-002 动手前先核内核 config 与符号来源
- 症状：漏洞能触发但利用链缺环；子系统调不通
- 判断：触发链每一步都有对应 CONFIG_ 项（USER_NS/USERFAULTFD/BPF/NET_SCHED）→ 缺一个整链断
- 动作：按 /proc/config.gz 逐项核对 exp 要求的选项；BTF/vmlinux 取不到先解决符号来源
- 无效则：选项改不了（厂商锁死）→ 降级到只依赖已开子系统的路线
- 失效条件：GKI 设备上模块 config 在 vendor_dlkm 单独编译，主内核 config 不再代表全量
- 证据：strong ｜ 3源(52pj1/kanxue2) ｜ 2014–2014 ｜ 命中2

<a id="neihe-003"></a>
#### neihe-003 setenforce 0 后仍被拒 ≠ allow 问题
- 症状：关了 SELinux 还是 Permission denied；chcon 后重启就复原　报错：`Permission denied`；`avc: denied`

- 无效则：无（不改内核绕不过）
- 失效条件：未启 CONFIG_SECURITY_SELINUX 时不适用
- 证据：weak＋缺口 ｜ 2源(52pj0/kanxue2) ｜ 2026–2026 ｜ 命中12

## 阶段：定位

<a id="neihe-006"></a>
#### neihe-006 页表按级查表，Block 命中直接加 offset
- 症状：地址翻译错位；多走了一级页表；4MB 大页算错
- 判断：描述符命中 Block（或 PS=1 的 PDE）→ 该级就是最终物理基址，不该再下一级
- 动作：先读 TCR/TTBR 推级数与各级位数，逐级取索引；命中块就直接 块基址+页内 offset
- 无效则：级数算错 → 用 2^(64-T0SZ) 与 granule 反推每级 bit 数，别套默认 4K/48 位
- 失效条件：TGx 换 16K/64K 或 T0SZ 非默认值时各级位数改变，旧索引公式失效
- 证据：strong ｜ 3源(kanxue3) ｜ — ｜ 命中68
- 锚点：282187,282650,283411

<a id="neihe-007"></a>
#### neihe-007 page_shift 随 tg1 变，别写死 12
- 症状：同一份读页表代码换机型就错；4K/16K/64K 混用
- 判断：tg1 为 0/1/3 时 page_shift 是 12/14/16 → 写死 12 只在 4K 内核成立
- 动作：从 tcr_el1 取 tg1 与 t1sz 算 page_shift；描述符类型还要看级别（L3 的 11 才是 Page）
- 无效则：拿不到 tcr_el1 → 退到常量推断并标注不确定
- 失效条件：改 52 位 VA 或非标准 granule 组合时 12/14/16 三档不再覆盖
- 证据：strong ｜ 3源(kanxue3) ｜ 2024–2024 ｜ 命中11
- 锚点：282187,284417,285272

<a id="neihe-008"></a>
#### neihe-008 内核算符定位：导出优先，再特征码，最后 kallsyms
- 症状：找不到内核函数地址；换个版本全崩
- 判断：符号在 kallsyms/导出表可见 → 直接解析；不可见才上特征码或 kallsyms_lookup_name
- 动作：先用 kprobe 拿 kallsyms_lookup_name 万能寻址，再按名字取其余算符；无 root 从镜像符号表补
- 无效则：未导出 → 改 kprobe 注册后取地址，或转特征码
- 失效条件：【推断】5.7 起不再导出 kallsyms_lookup_name，且 kptr_restrict 限制非 root 时失效
- 证据：strong ｜ 3源(kanxue3) ｜ 2025–2025 ｜ 命中3
- 锚点：284674,286878,287383

<a id="neihe-009"></a>
#### neihe-009 未导出全局变量用「mov reg, cs:xxx」两步定位
- 症状：全局变量地址找不到；特征码满屏误报；PAGE 节里一堆命中
- 判断：命中 mov reg, 绝对地址 形态 → 目标地址 = 命中地址+指令长度+*(int*)(命中+3)
- 动作：只扫 .text，用 PAGE 节过滤压误报；解出位移字段后再回读一次验证指向
- 无效则：命不中 → 改从导出函数的交叉引用反查该变量归属的结构体
- 失效条件：内核开 PIE/RANDSTRUCT，或编译器把绝对寻址改成 PC 相对/GOT 时，两步法失效
- 证据：weak＋缺口 ｜ 3源(kanxue3) ｜ 2024–2024 ｜ 命中11
- 锚点：282756,282924,290922　依据在图中，未复核

<a id="neihe-011"></a>
#### neihe-011 UAF 触发前先过 RCU 宽限期，别急着喷
- 症状：释放后立刻喷没效果；对象还在没被 free；复现时好时坏
- 判断：释放走 RCU 回调 → 立刻喷射时对象还没真正 kfree，看着像漏洞不成立
- 动作：释放后 sleep 3 秒等到宽限期再喷射；用断点确认 kfree 真的执行过
- 无效则：不能等 → 在 synchronize 类同步点下手，或换非 RCU 释放路径的对象
- 失效条件：释放路径不走 RCU（直接 kfree）时无需等待，本条不适用
- 证据：weak ｜ 2源(kanxue2) ｜ — ｜ 命中2
- 锚点：283073,289370

<a id="neihe-012"></a>
#### neihe-012 找「先复制字段、后解绑旧对象」的计数错减
- 症状：替换对象后计数变负；删除时提前放行释放；引用计数看着没问题
- 判断：复制旧对象字段后又对旧对象 put/unbind → 语义上不该减，计数可降到 <=0 放行释放
- 动作：在 change/replace 类函数里找复制+解绑组合，跟踪计数到负数，再看 delete 判 <=0 的路径
- 无效则：计数路径太长 → 先断点观察计数变化，再回推多余的那一减
- 失效条件：上游给该路径补了计数校验或改成原子引用计数后，错减不再可累积
- 证据：weak ｜ 2源(kanxue2) ｜ — ｜ 命中12
- 锚点：283073,284535

<a id="neihe-023"></a>
#### neihe-023 改硬件指纹先找唯一数据源：SMBIOS 表
- 症状：序列号改了又复原；反作弊读到原值　报错：`STATUS_OBJECT_NAME_EXISTS`
- 判断：序列号由固件填进物理内存 SMBIOS 表 → 改表比逐个 hook 干净；表已注册，覆盖必失败
- 动作：用「_SM_ + 偏移 16 校验 _DMI_」双签名定位 EPS，再从 WmipFindSMBiosStructure 取地址与长度改表
- 无效则：只读 hook 不够 → 跟写入路径，或走虚拟化（需 VT）
- 失效条件：平台改用其他固件接口，或 HVCI 禁止写只读内存时失效
- 证据：weak＋缺口 ｜ 2源(kanxue2) ｜ 2024–2024 ｜ 命中3
- 锚点：282756,285805

## 阶段：校验

<a id="neihe-013"></a>
#### neihe-013 双版本反汇编并列，看链表操作是否真执行
- 症状：单版本读代码看不出问题；链表节点没被摘掉；漏洞在新系统上不可复现　报错：`0xc0000409`；`FAST_FAIL_INVALID_REFERENCE_COUNT`
- 判断：新旧版本同函数并列，旧版少了摘链分支 → 是逻辑空洞，不是编译器优化
- 动作：取两版本同名函数对齐反汇编，重点比 Flink/Blink 摘链与校验分支；再用写断点量化计数字段
- 无效则：只有单一版本 → 用写断点观察链表与计数在运行时的实际变化
- 失效条件：目标版本之间该函数被重写（结构/内联变化）时偏移对齐失效
- 证据：weak＋缺口 ｜ 3源(kanxue3) ｜ 2024–2025 ｜ 命中1
- 锚点：284535,284757,287619

<a id="neihe-014"></a>
#### neihe-014 Double Free 要变成「两指针共指一对象」的原语
- 症状：只能崩不能控；释放两次就没了；复现只到 panic
- 判断：只是重复释放触发检测 → 还不算成品；要能在第二次释放时指向目标结构体
- 动作：先证明两个指针指向同一对象，再用目标 slab 结构体承接第二次释放，最后验读写确实落到该对象
- 无效则：释放相邻对象触发 double-free 检测 → 释放间插入间隔对象打散
- 失效条件：内核开 SLUB debug / CONFIG_SLAB_FREELIST_HARDENED 时须先处理检测再谈原语
- 证据：weak＋缺口 ｜ 3源(52pj1/kanxue2) ｜ 2014–2025 ｜ 命中39
- 锚点：280741,281448,287859

<a id="neihe-015"></a>
#### neihe-015 目标结构在专用 slab 时先归还整页再承接
- 症状：喷射命中不到 cred/file；slabinfo 里对不上
- 判断：cred/file 在专用 slab cache → 普通堆喷命中不了，必须 cross-cache
- 动作：先把漏洞对象所在 slab 整页释放回页管理器，再大量分配目标结构体占同一页；slabinfo 看页归属
- 无效则：页面回收不掉 → 换同 size kmalloc cache 里可控的承接对象
- 失效条件：开 CONFIG_SLAB_VIRTUAL 或随机化 freelist 后页复用规律改变
- 证据：weak＋缺口 ｜ 3源(52pj1/kanxue2) ｜ 2014–2026 ｜ 命中6
- 锚点：280741,288890,293309

<a id="neihe-016"></a>
#### neihe-016 先确认能不能让 copy_from_user 停住
- 症状：竞争窗口太小；userfaultfd 不可用
- 判断：检查与写入之间窗口不够 → 需要可 stall 的 user copy，被禁就得换机制
- 动作：先测 userfaultfd（vm.unprivileged_userfaultfd），不可用改 fallocate PUNCH_HOLE+KEEP_SIZE 制造缺页等待
- 无效则：都不可用 → 文件锁或大块刷新类延时，只能延缓
- 失效条件：内核默认关闭非特权 userfaultfd（5.11+）时老 exp 前置不成立
- 证据：weak＋缺口 ｜ 3源(kanxue3) ｜ 2026–2026 ｜ 命中8
- 锚点：289370,284418,290379

<a id="neihe-024"></a>
#### neihe-024 抹 PoolBigPageTable 条目必须在释放前还原
- 症状：抹表后卸载驱动蓝屏；反作弊扫大页找到驱动　报错：`BugCheck`
- 判断：内核释放大页时也查该表 → 条目被抹就查找失败 BugCheck，抹项并非无损
- 动作：按 ExFreeHeapPool 的索引算法算槽位（表项 0x18）做前后扫描对比；抹前存原值，释放前还原
- 无效则：不动表 → 改 Hook ExpAddTagForBigPages 不记录，释放路径同样要自洽
- 失效条件：版本改变该表结构与索引算法（实测 Win11 25H2 表项 0x18）时公式与偏移全部重算
- 证据：weak＋缺口 ｜ 2源(kanxue2) ｜ — ｜ 命中11
- 锚点：285355,290922　依据在图中，未复核

## 阶段：补丁

<a id="neihe-025"></a>
#### neihe-025 ARM64 打补丁先算 imm26：偏移/4 且限 ±128MB
- 症状：patch 后跳飞；目标超出 B 范围　报错：`目标超出 B 指令范围`
- 判断：B/BL 的 imm26 编码的是「指令条数差」→ 不 <<2 必跳错；范围只有 ±128MB
- 动作：偏移除 4 再 &0x3FFFFFF，写回 0x14000000|imm26；先验 4 字节对齐与同段，跳板造在 .text 空区
- 无效则：超 ±128MB → 改 BR 经寄存器或就近造跳板两段跳
- 失效条件：目标跨段/超 ±128MB，或指令已被厂商改成 BR 形态时该编码不适用
- 证据：strong ｜ 3源(kanxue3) ｜ 2026–2026 ｜ 命中12
- 锚点：283541,290412,291937

## 阶段：验证

<a id="neihe-017"></a>
#### neihe-017 喷射前拉高 RLIMIT_NOFILE 并绑核
- 症状：exp 时好时坏；喷射命中率低；换机器成功率骤降
- 判断：命中不稳多因 fd 上限不够，或分配落点受 CPU 核数影响
- 动作：RLIMIT_NOFILE 拉到 14096，失败降级 4096 并减喷射量；taskset 绑核，再调 middle/end 参数
- 无效则：仍不稳 → 换长期持有的载体，别靠堆次数硬怼
- 失效条件：内核开启 per-cpu 缓存记账变更后，落点分布规律改变需重测
- 证据：weak＋缺口 ｜ 3源(52pj1/kanxue2) ｜ 2014–2026 ｜ 命中6
- 锚点：280741,291053,291662

<a id="neihe-018"></a>
#### neihe-018 喷射载体优先选能长期持有且可 mmap 的
- 症状：喷射同刻只有一个对象；命中一次就没了；ctl_buf 抢不到
- 判断：载体用完即释放 → 同一时刻只能存在一个，只能靠多线程竞争
- 动作：按目标 slab 大小选 pg_vec/msg_msg/sk_buff 这类可长期持有、且能从用户态 mmap 直写的载体
- 无效则：只能用它 → 配多线程条件竞争并放大窗口
- 失效条件：加固内核限制 AF_PACKET 大页环或 msg_msg 大小时该载体不可用
- 证据：weak ｜ 2源(kanxue2) ｜ 2026–2026 ｜ 命中2
