## 阶段：侦察

<a id="tuoke-001"></a>
#### tuoke-001 先用 assets 与 lib 的 so 名做零成本查壳定性
- 症状：不知道是什么壳；查壳工具给不出结论
- 判断：libjiagu.so→360、libshella/libDexHelper→梆梆 → 固定 so 名就是厂商指纹，比查壳工具快，还顺带定下用哪套入口类名
- 动作：解包后列 assets/ 与 lib/ 的文件名对一眼，命中即定厂商分支
- 无效则：文件名被改 → 回退读清单入口类名（tuoke-002）
- 失效条件：厂商随机化 so 名、或运行时从 assets 释放而不在磁盘留固定名时失效
- 证据：strong ｜ 3源(52pj3) ｜ 2021–2025 ｜ 命中15
- 锚点：1377608,2081208,1918003

<a id="tuoke-002"></a>
#### tuoke-002 按清单 android:name 认壳入口类
- 症状：不知道壳入口在哪；hook 不到壳类
- 判断：android:name 是共性壳入口名（StubApp / TxAppEntry / WrapperProxyApplication / com.mx.dA.dpa）→ Application 已被换成代理，脱壳与 hook 都从它的 attachBaseContext 起
- 动作：读清单记 android:name 与 appComponentFactory，改时两处一起改；对不上已知壳就拿类名回搜壳 dex
- 无效则：清单被加密读不出 → 走 assets/lib 文件名反推（tuoke-001）
- 失效条件：壳改用 meta-data 约定值或自研反射装载、android:name 直指业务类时，此判据不再指向壳入口
- 证据：strong ｜ 4源(52pj4) ｜ 2020–2021 ｜ 命中18
- 锚点：1416395,1151350,1327690,1129777

<a id="tuoke-003"></a>
#### tuoke-003 反编译能开但代码全灰先判加固，别怀疑工具
- 症状：代码全灰；包正常但没代码
- 判断：包结构完整、类都在、方法体全空 → 壳把真 dex 留到运行时才释放，换工具只是白做一轮；工具没报加固也不等于没加固
- 动作：用 MT / NP / GDA 看一眼加固标识后直接转脱壳，顺手核对 dex 结构是否异常
- 无效则：能直接读到业务代码 → 先装一遍再看，通了就跳过脱壳
- 失效条件：反编译工具自身的 dex 校验或解析缺陷也会造成大面积空方法，现象相同而根因在工具
- 证据：strong ｜ 4源(52pj4) ｜ 2019–2024 ｜ 命中22
- 锚点：1029820,1026370,1416395,1918003

<a id="tuoke-004"></a>
#### tuoke-004 先按保护粒度与代次定壳类型，再选脱法
- 症状：不知道是哪种壳；方案试了都没出东西
- 判断：整 dex 不可读但类结构完整 → 整文件壳，内存 dump 就够；方法体被抽空 → 抽取壳，dump 后还要回填 code_item；关键方法变 native → java2c/vmp。判错等于整轮白干
- 动作：三问定型：方法体是否空、关键方法是否 native、lib 里是否多出业务无关的 so
- 无效则：三问互相矛盾 → 按混合壳处理，先脱最外层整体加密
- 失效条件：同一 APK 混合多代（整体加密＋抽取＋native 化）时，单一类型标签不足以决定脱法
- 证据：strong ｜ 4源(52pj2/kanxue2) ｜ 2017–2024 ｜ 命中11
- 锚点：281005,284629,570028,1865310

<a id="tuoke-005"></a>
#### tuoke-005 方法体全 nop 判抽取壳；回填 code_item 前先确认原位还在
- 症状：大面积空方法；脱壳后函数体还是空
- 判断：jadx 能开、方法体全是 nop 或只有 return → 抽取壳，磁盘 dex 里本来就没有指令，被抽掉的只有 insns；而壳重编译过或改过偏移时，「写回原位」这个前提本身就失效
- 动作：停静态读，改走主动调用逼壳回填或解释器入口插桩；抽取是懒回填，先建 基址→size 去重表；回填前先确认 code_item 偏移在 dex 里存在且长度够
- 无效则：偏移不在 dex 本体里 → 反编译重写 smali 回编译，或做 dex 内存重组
- 失效条件：壳改成一次性全量回填而非懒回填时，等待策略与去重 key 都要改；code_off 指向文件外时，按 dex 内偏移回填必然错位
- 证据：strong ｜ 5源(52pj5) ｜ 2015–2025 ｜ 命中14
- 锚点：1135060,1576245,405255,2008061,1939665

<a id="tuoke-006"></a>
#### tuoke-006 IDA 打不开或满屏乱码就转 so 层路线
- 症状：IDA 打不开 so；字符串整片乱码
- 判断：ELF 头或节表被改、字符串表整片乱码、imports 出现不像函数名的怪串 → so 层壳，继续脱 dex 无用
- 动作：先 readelf 看段与符号，再转 .init_array + JNI_OnLoad 找解密函数
- 无效则：只是少量字符串乱码 → 按 ollvm 字符串混淆处理，别当 so 层壳
- 失效条件：壳在 .init_array 之前就靠自实现 linker 完成解密时，构造函数里找不到解密逻辑
- 证据：strong ｜ 4源(52pj4) ｜ 2019–2023 ｜ 命中62
- 锚点：1743378,1489271,1085438,1036960

<a id="tuoke-035"></a>
#### tuoke-035 先判硬墙与收益再决定投多少
- 症状：脱完壳发现没法改；花了很久收益很低
- 判断：抓包看不到业务数据下发、或核心逻辑在 native 且关键类不齐 → 脱壳只换来调试环境干净，不是能读代码，投入产出比极低
- 动作：先抓一次完整业务请求看响应是否带真实内容，再看 lib 里 il2cpp/Unity 特征；硬墙之一成立就评估换路线
- 无效则：数据已下发但客户端仍拦 → 才值得继续脱壳与改判断
- 失效条件：业务改成客户端全量下发、服务端只做完整性校验后，服务端硬墙这条判据不成立
- 证据：strong ｜ 3源(52pj3) ｜ 2019–2020 ｜ 命中103
- 锚点：1332737,1029891,1186662

## 阶段：定位

<a id="tuoke-009"></a>
#### tuoke-009 脱壳点沿 DefineClass 到 LoadMethod 依次试，三问齐备才算
- 症状：不知道在哪下断；dump 出来是残片
- 判断：任何壳最终都要把明文 dex 交给 ART → 加载链上必经的函数最可靠；候选点要同时满足「拿得到起址＋拿得到大小＋时机在解密之后」，缺一项就是残片
- 动作：从 ClassLinker::DefineClass 起 hook，覆盖不全依次退到 DexFile::Open、LoadMethod；每换一点先过三问
- 无效则：三问都满足仍拿不到 → 壳已在调用点前恢复内存，改在更早的解密窗口取（tuoke-014）
- 失效条件：ART 换代重构加载链（vdex/cdex）、或壳把长度信息从 dex 头移走时，候选点与第二问的取法都要重查
- 证据：strong ｜ 4源(52pj4) ｜ 2015–2020 ｜ 命中2
- 锚点：1244889,1121372,1011717,405255

<a id="tuoke-010"></a>
#### tuoke-010 找解密点先搜 mprotect，再退到必然调用的系统 API
- 症状：找不到壳的解密函数；so 太大无从下手
- 判断：解密代码段必然要改内存权限 → mprotect 处就是解密窗口边界；全被内联或 svc 直调绕过时，mmap/open/dlsym/pthread_create 是壳必须调的
- 动作：搜 mprotect 与这四个 API，调用前后下断，按调用栈回落到壳 so 内的 caller，dump 落在窗口内
- 无效则：搜不到 mprotect → 搜 mmap 的「长度＋保护属性＋返回值」对齐指纹；API 断点也落空就转 svc 搜索（tuoke-023）
- 失效条件：壳改用自实现页表操作、提前把段设为常驻可写、或用 svc 直调加函数表索引调用时，两类断点都不成立
- 证据：weak＋缺口 ｜ 4源(52pj2/kanxue2) ｜ 2020–2024 ｜ 命中7
- 锚点：280302,282460,1103857,1091374

<a id="tuoke-013"></a>
#### tuoke-013 dex 落点看匿名 rw 段，长度从寄存器读，别扫魔数
- 症状：dump 出的 dex 被截断；不知道 dex 在内存哪段　报错：`newPosition > limit`
- 判断：dex 落在 zero 匿名映射、无文件后备、rw- → 运行期解密产物；扫魔数定边界必然截断：魔数可抹，vdex 头也会被误认
- 动作：Ctrl+S 锁定匿名 rw 段，起址与长度取寄存器或 0x20 的 file_size，产物按 tuoke-028 修头
- 无效则：file_size 也被抹 → 用 maps 区间长度反推，再用 jadx 关校验验证
- 失效条件：多个 dex 拼在同一段连续内存共用一块分配、或壳直接映射成有文件后备的段时，两个判据都不成立
- 证据：strong ｜ 4源(52pj4) ｜ 2020–2024 ｜ 命中19
- 锚点：1103857,1093821,1121372,1961813

<a id="tuoke-014"></a>
#### tuoke-014 对「用完就擦」的壳必须在解密窗口内 dump
- 症状：dump 晚一步拿到密文；报访问越界　报错：`Error: access violation accessing 0x`
- 判断：报错地址恰是认作 dex 起点那个 → 地址对了、时机错了：壳「临时映射、读完立刻 munmap/memset」，现役 360 即如此
- 动作：在解密函数前后设断，dump 放在窗口内；撞上临时映射就换支持该模式的成品工具，别反复重试同一把
- 无效则：窗口太窄抓不住 → 在 mprotect 或 mmap 返回处 hook 取数
- 失效条件：壳把解密结果常驻保留（无擦除动作）时窗口限制消失，任意时刻 dump 都可
- 证据：strong ｜ 3源(52pj3) ｜ 2019–2025 ｜ 命中19
- 锚点：1005352,1085438,2069979

<a id="tuoke-016"></a>
#### tuoke-016 hook 加固 App 找不到类先取壳入口的 ClassLoader
- 症状：hook 不到类；hook 加固 App 没反应　报错：`java.lang.ClassNotFoundException`
- 判断：类名核对无误却 ClassNotFoundException → 不是名字错，是 loader 不对：壳在 attachBaseContext 阶段才把真 dex 挂到自己 loader 上
- 动作：hook 壳入口类 attachBaseContext，after 里用 param.args[0].getClassLoader() 取真 loader；重载方法写全签名
- 无效则：壳入口也动态取 loader → 从 ActivityThread 或当前线程栈取
- 失效条件：在 attachBaseContext 之前取、或壳把 dex 挂到别的 loader 上时，拿到的是壳 loader
- 证据：strong ｜ 4源(52pj3/kanxue1) ｜ 2019–2024 ｜ 命中32
- 锚点：279381,1029891,1988373,1405170

<a id="tuoke-018"></a>
#### tuoke-018 脱壳工具按适用边界选，失败就换别反复调同一把
- 症状：脱壳工具卡住；同一工具反复报错　报错：`all done 之后产物是空壳`
- 判断：壳与工具一对一适配 → 一把卡住不代表样本没救；按固定 magic 扫描的老 dumper 在壳抹魔数或延后映射时一律扫不到，只能当「是否整体加密」判据
- 动作：备三套并记各自失败形态：内存搜特征系 → 成品工具 → 自研 hook；老 dumper 只留判壳代数一个用途
- 无效则：三套全败 → 回壳类型判断（tuoke-004），多半是类型判错
- 失效条件：壳统一反所有公开工具、或厂商回头用落地加载式简单加密时，「换工具」与「老 dumper 扫不到」两条都要重估
- 证据：strong ｜ 4源(52pj4) ｜ 2020–2025 ｜ 命中5
- 锚点：2069979,2081184,1941260,1140947

## 阶段：校验

<a id="tuoke-020"></a>
#### tuoke-020 返回值型反调试先在调试器里改寄存器，别急着落盘
- 症状：附加调试后进程退出；过了反调试还是被杀
- 判断：检测结果放 R0、后面 cmp 再条件跳 → 调试期改寄存器是单点操作，不动代码段、不破完整性校验；把 00 20 写进 so 属落盘补丁，会被 CRC 抓到。结果落在分支选择寄存器时改选择值（1091374 改 R2=0x1C），不是一律置零
- 动作：调试期：cmp 前把 R0 置零或 F4 跳过比较，验收是继续跑不崩；要落盘才改机器码并先处理校验（tuoke-030）
- 无效则：置零后仍崩 → 该检测还承担初始化副作用，改为跳过整段检测
- 失效条件：结果从 R0 改到内存标志位、判定不再是 cmp、或同一检测被复制到多区段（tuoke-021）时，单点置零不成立
- 证据：weak ｜ 2源(52pj2) ｜ 2020–2020 ｜ 命中2
- 锚点：1103857,1091374

<a id="tuoke-021"></a>
#### tuoke-021 反调试按调用点计数，不按函数计数
- 症状：改完一处还是被杀；看不出漏在哪
- 判断：壳把同一段检测复制到多个区段甚至多份 so → 代码字节完全一致，但改了一份不影响另一份拷贝
- 动作：每进一次壳 so 都 F7 进去重新确认是不是上次那个函数；按模块名过滤，不在目标 so 就继续跑
- 无效则：确认只剩一处仍被杀 → 转向完整性校验或后台线程
- 失效条件：壳改成集中式总控（一处开关管全部检测）后，重复拷贝消失，按调用点计数就过度处理了
- 证据：weak ｜ 2源(52pj2) ｜ 2020–2020 ｜ 命中4
- 锚点：1103857,1306289

<a id="tuoke-022"></a>
#### tuoke-022 .init_array 与 JNI_OnLoad 是反调试的常驻点
- 症状：静态看不到反调试；一上调试就断不下来
- 判断：两处都在主界面之前执行 → 是放反调试与自校验的标准位置；典型形态是起线程查 TracerPid 或扫 23946 端口
- 动作：拿到 so 先扫这两段；见到 fork / pthread_create / 读 /proc/self/status 就当反调试
- 无效则：两处都干净仍跑不起来 → 转 Java 层 static 块里的 isDebuggerConnected
- 失效条件：壳把反调试改到 Application 首帧之后或延迟数秒触发时，两处常驻点不再是全部
- 证据：strong ｜ 3源(52pj3) ｜ 2019–2020 ｜ 命中53
- 锚点：1036960,1091374,1101220

<a id="tuoke-024"></a>
#### tuoke-024 改校验的比较结果或调用点，别改被复用的比较函数
- 症状：改了校验别处就崩；校验常量搜不到
- 判断：签名/CRC 校验的布尔结果通常落在单一寄存器（如 r5）→ 0 改 1 比改跳转更少破坏后续逻辑；改被复用的 strcmp/memcmp 包装函数会连带影响别处。真要动 memcmp，长度是第三个参数（ARM 下 R2），置 0 恒等
- 动作：先改比较结果寄存器，或只改引用少的调用点；CRC 类自校验不要伪造值，废掉比较后的分支（tuoke-030）
- 无效则：比较被内联展开、没有单一结果寄存器 → 只能改判定后的分支
- 失效条件：壳把比较改成逐字节内联展开、不再调用 memcmp 时，长度参数这条路消失
- 证据：weak ｜ 2源(52pj2) ｜ 2019–2020 ｜ 命中9
- 锚点：1306289,1005352

<a id="tuoke-025"></a>
#### tuoke-025 校验分层逐层找齐：先对齐路径/fd/PMS 签名再谈过签
- 症状：改完只有部分功能生效；重签名后卡屏
- 判断：校验分层、分时机触发 → 只改 Java 层只能放开一层；校验也不只比签名：getApkPath 的路径、open 的 fd、PMS 的签名任一项不一致都可能被抓，进程活着日志无异常却卡住多是 native 主动阻塞
- 动作：三者对齐后再谈过签；每过一层就全局搜同一特征串，逐层推进；文件访问盯 openat
- 无效则：对齐后仍卡 → 查 supportVulkan 这类旁路读签名的入口；层太多就先找总控「门闩」
- 失效条件：校验改成服务端下发开关、客户端只读结果时不成立；Android 引入 getApkContentsSigners 一类新接口后旧 PMS hook 点不再被调用
- 证据：strong ｜ 4源(52pj4) ｜ 2020–2020 ｜ 命中3
- 锚点：1310498,1186662,1332737,1227128

## 阶段：补丁

<a id="tuoke-019"></a>
#### tuoke-019 加壳 so 打不开先修 ELF 头，再 dump 内存镜像
- 症状：IDA 打不开壳 so；导入导出表全空
- 判断：e_shnum/e_phnum 出现 0xff 一类非法值 → 壳只把数值改坏并未删段，改回同类 so 的量级就能开门；导入导出表全空说明链接在装载时才完成
- 动作：先按正常 so 的量级改写头字段；开不了门就 frida dump 内存段、soFixer 按模块基址修
- 无效则：dump 出来仍是残缺模块 → 等父模块做完内存偏移修正后再 dump 一次
- 失效条件：壳把节表整体搬走重排偏移、或对 so 做运行期分块解密时，改头与一次性 dump 都不成立
- 证据：weak＋缺口 ｜ 4源(52pj2/kanxue2) ｜ 2021–2025 ｜ 命中45
- 锚点：285153,287899,1489271,2067386

<a id="tuoke-027"></a>
#### tuoke-027 回填按清单逐项清，缺一件就闪退
- 症状：回填后启动闪退；壳逻辑仍生效
- 判断：只换 dex 不改清单 → 加载器配置与新 dex 布局不匹配，启动即崩或黑屏；真入口名常以字符串常量躺在壳入口类 <clinit>（sApplicationName 一类）；旧 dex 不删则加载顺序不可控
- 动作：修 dex → 从壳入口 clinit 抄回真实 android:name → 删 appComponentFactory → 删旧 dex 与壳 so/assets → 去签重签名
- 无效则：换回入口后仍起不来 → 查 native 层二次校验（tuoke-025）
- 失效条件：壳从网络或加密配置解析入口名时静态常量里找不到真入口；一代壳上出现过「不重签名能跑、自己重签名反而失败」（279402），此时重签名不是末步
- 证据：strong ｜ 4源(52pj4) ｜ 2020–2021 ｜ 命中4
- 锚点：1416395,1109463,1327690,1129777

<a id="tuoke-028"></a>
#### tuoke-028 修 dex 头按 file_size、SHA-1、Adler32 顺序
- 症状：反编译报结构错；拼接后加载不了　报错：`newPosition > limit`；`zip END header not found`
- 判断：三个头的覆盖范围是嵌套的 → 顺序错会让后一步把前一步算进去，白算；工具 exit 0 但 jadx 报错就是未修复的 dex
- 动作：file_size(0x20) → signature SHA-1(0x0c，从 0x20 起算) → checksum Adler32(0x08，从 0x0c 起算，小端)
- 无效则：修完仍报错 → 关掉 jadx 的 dex 校验只用于定位，真正的解仍是修头
- 失效条件：壳把 dex 拆成非标准分块（多 dex 共用段、code_off 指向文件外）时，三字段修复不足以让加载器接受
- 证据：strong ｜ 4源(52pj4/kanxue0) ｜ 2020–2024 ｜ 命中24
- 锚点：1287269,1129777,1961813,1416395

<a id="tuoke-030"></a>
#### tuoke-030 so 里改字节必须等长，短了补 00
- 症状：改 so 后崩溃；改完静默失效
- 判断：段偏移写死 → 长度一变后续偏移全部平移，表现为崩溃或静默失效；短路用 BLX LR 覆盖入口压栈指令，条件跳转只动 0xD0xx→0xE0xx 这类固定位
- 动作：等长替换、不足补 00；必须变长就挪到段尾空白区改指针，或改调用方
- 无效则：改完跑飞 → 先查 CRC 或低字节求和自校验，转 tuoke-024 改判定
- 失效条件：so 带 CRC 或低字节求和自校验时改任意字节都会被抓；代码段做了 SMC（运行期才解密）时写明文 NOP 会解出乱码，必须先把 patch 字节按同一算法加密再写回
- 证据：strong ｜ 3源(52pj3) ｜ 2019–2020 ｜ 命中19
- 锚点：1306289,1005352,1085438

#### tuoke-032 自实现 linker 的 so 按 d_tag 把抽走的表原样粘回
- 症状：IDA 里 so 缺 phdr 与重定位表；修复后仍加载失败
- 判断：被抽走的 phdr、.rela.plt、.rela.dyn、.dynamic 是被覆盖而不是被删除 → 原位与大小都不变，可以原样回填

- 失效条件：壳不仅覆盖还改了段大小或重排段顺序时，原样粘回的前提失效
- 证据：strong ｜ 3源(kanxue3) ｜ — ｜ 命中7

#### tuoke-034 按 L包名/类名; 的出现次数筛产物，只反编译最多那个
- 症状：产物几十个 dex；不知道哪个是真的
