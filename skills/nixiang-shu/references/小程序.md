## 阶段：定位

<a id="xiaochengxu-003"></a>
#### xiaochengxu-003 用必要性实验加两级搜索定住被校验的签名参数
- 症状：改完参数报验签失败；不知道哪个 header 必传；静态搜不到签名参数名
- 判断：删或改该参数后服务端报错、其余字段可照抄 → 它就是被校验的那个；参数名与值的固定前缀都搜不到 → 字符串被运行时拼接或编码。
- 动作：先做消融：只加密不改 sign、或逐个删 header 看服务端反应；静态按参数名、值前缀两级搜；两级皆空即转调试器断点，不再读全量混淆代码。
- 无效则：转开发者工具单步，把中间值记成数据流
- 失效条件：签名逻辑下沉到 so 或 VMP，参数名与值前缀都不在 JS 层
- 证据：weak＋缺口 ｜ 3源(52pj2/kanxue1) ｜ 2021–2022 ｜ 命中4
- 锚点：1471424,1722264,287064

#### xiaochengxu-007 密文定位不了就劫持响应塞脏字符，让报错栈指路

- 判断：响应被改成非法字符后小程序解密必然抛错 → 控制台报错栈直接指向 decrypt 或 encrypt 函数，比静态翻混淆代码快。
- 动作：抓包工具劫持响应把内容替换成 !!!!!@@@@@ → 控制台看栈定位加解密函数 → 再把函数与密钥导出到 globalThis 供 JsRpc 调用。
- 无效则：若失败被 try/catch 吞掉，改断点或改日志开关
- 失效条件：解密失败被静默兜底且不打日志，栈里看不到真实函数
- 证据：weak＋缺口 ｜ 2源(kanxue2) ｜ 2025–2026 ｜ 命中7

#### xiaochengxu-008 密钥落在 globalData 就改走运行时取值
- 症状：密钥每次不同；算法逆不动；要批量解历史包
- 判断：看到密钥被赋给 app.globalData 这类跨页面共享的运行时数据 → 运行期一定可读，逆云数据库或协议不如直接取值。
- 动作：断点作用域里直接求值取字段；或把解密函数与密钥导出到 globalThis 后注册 JsRpc，在数据包入库前解出明文。
- 无效则：转反编译静态读赋值点，再运行时验证
- 失效条件：密钥不再留在 globalData 而只存在于闭包或 so 内
- 证据：weak＋缺口 ｜ 2源(kanxue2) ｜ 2025–2025 ｜ 命中11

## 阶段：校验

<a id="xiaochengxu-004"></a>
#### xiaochengxu-004 小程序签名多是编码游戏，先按自定义字符表处理
- 症状：签名串超长且无填充；签名字符集含 +/；报签名不一致
- 判断：签名是超长串、含 +/ 却无等号填充、长度与任何标准哈希都不符 → 自定义字符表的字符串转数组再换表编码，没有密钥只有置换规则。
- 动作：在断点里把每步中间数组与索引逐笔记下，按数据流复现；验收以真实抓包体的 sign 逐字符一致为准，不一致就固定 common 各字段再调。
- 无效则：若命中 hexMD5 等标准实现，直接换标准 MD5 跑通
- 失效条件：签名计算被搬进 VMP 或 so（出现 __TENCENT_CHAOS_VM 一类特征）
- 证据：weak＋缺口 ｜ 3源(52pj2/kanxue1) ｜ 2021–2025 ｜ 命中30
- 锚点：1471424,1722264,286197

<a id="xiaochengxu-011"></a>
#### xiaochengxu-011 改包前先确认校验在参数层还是服务端开关
- 症状：改参数重发失败；重发原包却成功；改了 URL 也失败
- 判断：原包重发成功、改任一参数失败 → 校验在参数层（header 里的 sign、时间戳、字段名列表），与服务端开关无关。
- 动作：先用差分定位必传项，再用抓包工具的魔术方法在请求发出前实时重算签名，失败的字段就是参与签名的字段。
- 无效则：转运行时导出签名函数，用 JsRpc 代理重算
- 失效条件：服务端改为签名加一次性随机数，重算后仍不可重放
- 证据：weak＋缺口 ｜ 3源(52pj1/kanxue2) ｜ 2022–2025 ｜ 命中5
- 锚点：287341,287486,1722264

<a id="xiaochengxu-014"></a>
#### xiaochengxu-014 Node 补环境必须用真机抓包体回测，逐字节一致才算过
- 症状：算出的参数过不了校验；参数长度偏短；开发者工具产出的值无效
- 判断：开发者工具或 PC 端产出的参数被服务端识别（典型是长度偏短）→ 环境不对，不是算法不对。
- 动作：逐个按报错补 wx 系 API 依赖的环境参数（如宿主版本号），再用真机重放同一请求体逐字节比对，一致才算通过。
- 无效则：补不全时改为在真机运行时直接调用原函数生成
- 失效条件：服务端加设备指纹绑定，只补环境参数无法通过
- 证据：weak＋缺口 ｜ 2源(kanxue2) ｜ 2025–2025 ｜ 命中1
- 锚点：283125,286197

#### xiaochengxu-002 反编译产物先修到能编译，否则没有动态入口
- 症状：开发者工具编译报错；插件未授权使用；编译停住没流量　报错：`插件未授权使用`；`unexpected token `{``；`module 'utils/tools/xxx.js' is not defined`
- 判断：看到开发者工具编译中断 → 小程序一条业务请求都不会发 → 抓包为空不是抓包问题，是编译没通过。
- 动作：按序修三类阻断：app.json 的 plugins 声明整段删；WXSS 开头原生 CSS 变量裸块删；报模块未定义就单独反编译对应 wxapkg 分包盖回 __APP__ 再格式化。
- 无效则：换版本更低或更高的开发者工具重试
- 失效条件：开发者工具开始接受插件授权与原生 CSS 变量（新版该类报错消失）
- 证据：weak＋缺口 ｜ 3源(kanxue3) ｜ 2025–2025 ｜ 命中2
- 锚点：287063,287065,287069
