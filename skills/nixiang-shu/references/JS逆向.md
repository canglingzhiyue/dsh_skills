## 阶段：侦察

<a id="jsfx-001"></a>
#### jsfx-001 先存一份真实成功请求当金标准
- 症状：复现结果与线上不一致；换参数就复现不了
- 判断：只有构造样例时，漏掉的盐与时间戳全靠猜；握有一份真实入参+密文，任何一层都能立刻比出对错。
- 动作：抓一次成功请求，落盘 URL、全部入参、密文、cookie 当基准，之后每层打印都与它逐字比。
- 无效则：抓不到成功请求 → 先解决登录与风控，别急着读算法。
- 失效条件：密文有状态（同入参两次不同）时单一样本不能充当"逐字一致"的唯一基准。
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中5
- 锚点：2134338,2084662

<a id="jsfx-002"></a>
#### jsfx-002 先判值在哪一层生成
- 症状：JS 里搜不到目标串；改了前端毫无反应
- 判断：目标串在 JS 资源里搜得到→JS 层；只在 JS 里见 wasm.xxx()/new Function→wasm 层；值由 native 提供→已下沉 so；响应体自吐 debug/errcode→服务端算。
- 动作：JS 资源、wasm 字符串表、so 字符串三处搜同一串，命中哪层从哪层下手。
- 无效则：三处全空 → 搜协议字段名与伴生参数，或按响应体反查。
- 失效条件：值在运行时拼接（源码与二进制都无整串）时搜索全空，判据失效。
- 证据：strong ｜ 3源(52pj3) ｜ 2026–2026 ｜ 命中10
- 锚点：2094731,2134455,2134068

<a id="jsfx-003"></a>
#### jsfx-003 认加密点靠值比对不靠变量名
- 症状：搜 sign 命中几百处；改的函数是死代码
- 判断：某层打印的入参与抓包值逐字一致 → 该层即生成点；叫 sign/encrypt 的反而常是通用库包装或死代码。
- 动作：从 send/fetch 往下逐层打印入参对齐金标准，一致的那层停手。
- 无效则：各层都不一致 → 查二次编码或截断（URL 编码、不可见字符）。
- 失效条件：输出含不可见字符或截断时肉眼比对会假阴性，必须落盘比字节。
- 证据：strong ｜ 3源(52pj3) ｜ 2023–2026 ｜ 命中18
- 锚点：2084662,2106666,1840995

<a id="jsfx-004"></a>
#### jsfx-004 三连特征判 JSVMP 别当普通混淆
- 症状：混淆代码读不懂；不知该清字符串还是插桩
- 判断：for(;;)+大 switch+[++[]] 类畸形三连→JSVMP；只有 call/apply 转发→普通混淆；case 只做跳转且真值在数组里→栈式解释器。
- 动作：三连命中就别读 dispatch，改打印分发条件值；只命中一两项按普通混淆做 AST 清洗。
- 无效则：判不准 → 先按普通混淆清一轮，读不通再回头判 VMP。
- 失效条件：解释器被编译成 wasm/字节码时 JS 侧三连特征消失，须按内存下手。
- 证据：strong ｜ 3源(52pj3) ｜ 2025–2026 ｜ 命中12
- 锚点：2116112,2084662,2073641

<a id="jsfx-005"></a>
#### jsfx-005 两次同入参结果不同就当有状态处理
- 症状：同一请求复现结果不同；偶尔对偶尔错
- 判断：同入参连跑两次结果不同 → 加密带会话/计数器/随机盐；有状态时任何"每次新建进程"的离线设计必白跑一轮。
- 动作：先跑两次比结果再定架构；有状态就一次初始化、多次调用，调用串行化。
- 无效则：结果相同但仍偶发不一致 → 查时间戳/随机源参与，做成可注入参数。
- 失效条件：服务端每次下发一次性 nonce 时，本地复用实例也拿不到跨请求一致的结果。
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中1
- 锚点：2134338,2130859

#### jsfx-006 搜不到就换词：用协议字段名不用通用词

- 失效条件：字段名由服务端下发且每次变化时，字段名不再是稳定搜索词。

<a id="jsfx-026"></a>
#### jsfx-026 按锚点稳定性排序选搜索起点
- 症状：不知从哪个关键词下手；换版本全失效
- 判断：文案/字段名与框架 API 名（send/fetch/toString/Date.now）不被混淆 → 安全锚点；函数名跨版本易变；_0xabc(0x132) 下标最不稳定。
- 动作：从高稳定锚点往低走；下标类只翻译命中的那几个，不做全文件反混淆。
- 无效则：文案被拆成 \uXXXX 或拼接 → 搜片段、方法名或错误码。
- 失效条件：打包器开字符串数组加密+运行时解密后，明文字符串锚点全部消失。
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2026 ｜ 命中5

<a id="jsfx-027"></a>
#### jsfx-027 wasm 找不到可读数据就从线性内存导
- 症状：wasm 搜不到串；f12 打不开 wasm
- 判断：控制流被扁平化、字符串表搜不到 → 数据都在线性内存，控制流让位于数据流。
- 动作：从 memories.$memory.buffer 按地址取 Uint8Array 再 TextDecoder 导出，或按函数索引写脚本调用。
- 无效则：内存也拿不到 → 判值由 native 提供，转 so 静态分析。
- 失效条件：wasm 开内存增长或 memory64 后固定 buffer 视图在 grow 时失效，需重取。
- 证据：weak ｜ 2源(52pj2) ｜ 2026–2026 ｜ 命中4
- 锚点：2094731,2134338

## 阶段：校验

<a id="jsfx-008"></a>
#### jsfx-008 长度只提假设，算法族要常量确认
- 症状：64 位不知道是什么；试算对不上
- 判断：32 位 hex → 先试 MD5；40 位 → SHA-1；64 位 → SHA-256 或 HMAC-SHA256 两者都可能，长度只能提假设。
- 动作：拿 123456 试算比对 e10adc3949…；64 位须找到 hmac_sha256 符号或密钥入参才算确认。
- 无效则：试算不符 → 查盐/前后缀拼接，或码表被换。
- 失效条件：输出外面包了 base64 或自定义码表时，长度指纹直接失效。
- 证据：strong ｜ 3源(52pj3) ｜ 2021–2026 ｜ 命中4
- 锚点：2125447,1542726,2116112

<a id="jsfx-014"></a>
#### jsfx-014 长串解出乱码先换码表再谈算法魔改
- 症状：base64 解出来是乱码；不报错但结果不对
- 判断：字母+数字+/+= 长串解出乱码却不报错 → 先怀疑码表被换（/ + = 最常被替换），再怀疑算法魔改。
- 动作：先在自定义字母表里找出 / + = 的替身再解；字节序不对再查位运算分组（>>2、&3<<4|>>4、&15<<2|>>6、&63）。
- 无效则：换码表仍乱码 → 与标准算法常量逐项比对取差分。
- 失效条件：码表随会话由服务端下发时，静态替换永远追不上。
- 证据：strong ｜ 3源(52pj3) ｜ 2025–2026 ｜ 命中7
- 锚点：2107542,2125447,2079071

<a id="jsfx-015"></a>
#### jsfx-015 用标准 IV 差分认魔改算法
- 症状：怀疑 MD5/SHA-1 被魔改；不知道改了几处
- 判断：日志出现 0x67452301/0xEFCDAB89/0x98BADCFE/0x10325476/0xC3D2E1F0→标准 MD5/SHA-1 家族，差多少就是改了多少。
- 动作：把日志初值与标准 IV 逐项比对取差分；初值一致就直接调库复算，不必逆压缩函数。
- 无效则：初值一致结果仍不符 → 查额外加盐、改轮数、输出字节序。
- 失效条件：IV 由自定义 K 表派生（无固定初值）时找不到可比对的常量。
- 证据：strong ｜ 3源(52pj3) ｜ 2026–2026 ｜ 命中13
- 锚点：2116112,2106666,2123850

#### jsfx-028 滑块轨迹判真看统计特征，不看像不像

#### jsfx-019 补环境按 Proxy 日志补，不按文档猜
- 症状：补了几十项仍跑不通；node 里报未定义

- 无效则：日志里全是无效辅助函数 → 判它在浏览器里有无实际作用，没作用就删而不是模拟。
- 失效条件：逻辑依赖真实时序/网络/GPU 时按日志补也补不出，成本反超真机 trace。
- 证据：weak ｜ 2源(52pj2) ｜ 2021–2026 ｜ 命中12

<a id="jsfx-020"></a>
#### jsfx-020 时序类指纹必须单调递增，不能给常量
- 症状：环境补齐但仍被静默判死；指纹混进参数
- 判断：performance.timing 给常量 → 检测把指纹静默混进参数，流程正常而结果错；时序必须单调递增。
