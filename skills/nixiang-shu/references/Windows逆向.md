## 阶段：侦察

<a id="win-001"></a>
#### win-001 先读节表判有无壳，再决定是否脱壳
- 症状：不确定有没有加壳；导入表只剩几项
- 判断：节名乱码/节可写/入口不在首节/SizeOfImage 远大于各节和 → 有壳，先脱壳再静态
- 动作：pefile 打印 Machine、AddressOfEntryPoint 与各节四元组，比 SizeOfImage 与节总和
- 无效则：节表正常且导入表丰富 → 跳过脱壳直接静态摸底
- 失效条件：伪壳或入口即自解密的目标节表完全正常，此判据不触发
- 证据：strong ｜ 3源(52pj3) ｜ 2010–2014 ｜ 命中10
- 锚点：52571,72374,259984

<a id="win-002"></a>
#### win-002 数据目录第 14 项非 0 就判 .NET，直接开 dnSpy
- 症状：分不清是壳还是 .NET；IDA 里全是解析不出的代码
- 判断：COM 描述符非 0 → IL 程序集，读汇编不如读 C#
- 动作：pefile 读 DataDirectory[14]，并在偏移处搜 BSJB 确认元数据头
- 无效则：COM 项非 0 但 dnSpy 报无法解析 → .NET 壳，先脱壳
- 失效条件：.NET Reactor/ConfuserEx 把元数据搬进壳段后，COM 项指向的节读不出 IL
- 证据：strong ｜ 4源(52pj4) ｜ 2015–2025 ｜ 命中35

#### win-003 从导入表认语言运行时，跳过整段阅读

- 无效则：导入表被压成 LoadLibrary+GetProcAddress 两项 → 转动态，不判语言
- 失效条件：静态链入（/MT、Go、Rust、易语言独立编译）时导入表不含运行时 dll
- 证据：strong ｜ 4源(52pj4) ｜ 2010–2026 ｜ 命中0

#### win-004 ASCII 与 UTF-16LE 双搜都空才判字符串加密
- 症状：搜不到成功或失败提示；有弹窗却搜不到那串文本
- 判断：两种编码都搜不到 → 字符串被加密或自定义编码，继续抠字符串是白费
- 动作：HxD 按 UTF-16LE 双字节再搜一遍；仍空则改看导入 API 反推功能段

- 失效条件：目标用自研编码表（查表还原宽字符）时，双编码直搜同样落空

<a id="win-005"></a>
#### win-005 先判注册校验类型，再决定要不要逆算法
- 症状：不知道该脱壳还是该逆算法；注册码改了没用
- 判断：本地常量/CRC→改跳转；机器码派生→逆生成式；有请求→网络验证；有狗→走 API 层
- 动作：断网跑一遍并看网卡调用与设备句柄，三种现象对应三条路径
- 无效则：断网后任意码都过 → 判为纯本地判定，直接走补丁
- 失效条件：客户端先本地判再补一次服务端复核时，单看断网现象会误判成本地

- 动作：在判定点前后各抓一次包，比对响应体是否已含关键字段
- 无效则：流量全加密看不到字段 → 先定接口加密，别盲改客户端
- 失效条件：服务端在下发接口里再校验一次时，首包看到已下发仍不等于本地判定

## 阶段：定位

<a id="win-008"></a>
#### win-008 压缩壳用 ESP 定律定 OEP：popad 后第一跳
- 症状：UPX/ASPack 脱完跑不起来；不知道 OEP 在哪
- 判断：入口后改 ESP 再唯一一次 popad → 其后第一个远跳转就是 OEP
- 动作：对 ESP 下硬件访问断点，命中后逐条过 popad，落点记作 OEP
- 无效则：没有 popad 收尾（花指令或改写后直接 jmp）→ 改看栈平衡点
- 失效条件：壳不用 pushad/popad 保存现场时，ESP 定律不命中
- 证据：strong ｜ 5源(52pj5) ｜ 2010–2018 ｜ 命中114
- 锚点：773961,609036,609026,58324,235696

<a id="win-009"></a>
#### win-009 加密壳不啃壳代码，改用系统 API 当断点锚点
- 症状：壳代码全是运算看不懂；VMP 里找不到业务入口
- 判断：壳要放明文必然调 VirtualAlloc/VirtualProtect/LoadLibrary → 断 API 比读壳省
- 动作：断 VirtualAlloc、VirtualProtect、LoadLibraryA，回调用者取解密结果
- 无效则：目标内联 syscall 绕 ntdll → 用户态 API 断点失效，转 trace
- 失效条件：壳自带内核驱动或全程 syscall 时，API 断点全部失守
- 证据：strong ｜ 3源(52pj3) ｜ 2012–2023 ｜ 命中8
- 锚点：147061,180693,1817473

<a id="win-010"></a>
#### win-010 dump 点定在解密完成且首次被消费之前
- 症状：dump 出来是乱码；dll 拿不到解密后的内容
- 判断：壳用完明文就 memset 擦掉 → 晚一步就没有，时机比 dump 工具重要
- 动作：先看明文落地位置，再在该处下内存访问断点，断下立即 dump
- 无效则：已经错过 → 换更早的解密入口重跑，别在残片上修
- 失效条件：壳按需分块解密时，一次性 dump 拿不到完整映像，只能按块重复
- 证据：strong ｜ 4源(52pj4) ｜ 2010–2023 ｜ 命中23
- 锚点：1026370,1865310,67701,347343

<a id="win-011"></a>
#### win-011 从提示字符串交叉引用入手，比从入口追快一个量级
- 症状：不知道校验在哪；主函数太长跟不下去
- 判断：成功或失败提示文案在代码里几乎只出现一次 → xref 直达判定分支
- 动作：字符串窗口定位后看引用，逐个函数比对哪条分支只影响提示
- 无效则：提示被加密搜不到 → 改看 MessageBoxA/W 调用点反查调用者
- 失效条件：提示走资源表 LoadString 间接取或控件自绘时，字符串引用断链
- 证据：strong ｜ 4源(52pj4) ｜ 2012–2023 ｜ 命中31
- 锚点：563437,140577,1778070,1573909

<a id="win-013"></a>
#### win-013 断在解密或校验函数入口，别断在比对处
- 症状：断在 strcmp 只看到结果；拿不到密钥
- 判断：入口能同时看到密文与密钥，出口只剩一个布尔结果
- 动作：对校验函数入口下断取参数指针，比对处只用于确认结论
- 无效则：函数被内联优化掉没有独立入口 → 断在调用链上一层或 API 层
- 失效条件：校验被拆成多段内联或搬进虚拟机解释器时不存在可断的函数入口
- 证据：strong ｜ 3源(52pj3) ｜ 2015–2017 ｜ 命中56

<a id="win-014"></a>
#### win-014 先认反调试属于哪类，再选绕过方式
- 症状：断点还没到进程就退出；随便一动就被杀
- 判断：PEB.BeingDebugged/ProcessDebugPort→改返回值；两次时间 API 相减→置 0；模块快照→过滤
- 动作：静态列检测点，按调用点地址去重计数后逐类处理，别按函数去重
- 无效则：同一保护在多区段反复调用 → 只堵一处的必被另一处杀，全 nop 或一个别动
- 失效条件：检测走直接 syscall 或自建内核对象时，用户态返回值篡改无效
- 证据：strong ｜ 5源(52pj5) ｜ 2017–2023 ｜ 命中8

## 阶段：校验

<a id="win-015"></a>
#### win-015 看到 E(输入)==常量且 E 不可逆，就别逆 E
- 症状：哈希怎么反推；要不要把算法完全还原
- 判断：比较式左边是密文右边是常量 → 不必还原 E，只需 D(常量) 或改 E 的入参
- 动作：把常量丢在线明文库或本地爆破；不成立就在 E 的入参处 hook
- 无效则：常量是分段拼接的多段哈希 → 转分段复算，别整体爆
- 失效条件：常量带随机盐或为空模板时，D(常量) 得不到原输入
- 证据：strong ｜ 4源(52pj4) ｜ 2016–2025 ｜ 命中34
- 锚点：1952584,677861,513172,2068987

<a id="win-016"></a>
#### win-016 分段哈希：段长从调用参数读，别猜
- 症状：长度固定却对不上；分段校验拼不起来
- 判断：调用形如 (ptr,7,...) 连续多次 → 逐段各自哈希后比硬编码 hex
- 动作：读调用参数里的段长与顺序，按序复算逐段比对，先查明文库
- 无效则：段长随输入变化 → 不是定长切分，改断在切分循环里看规律
- 失效条件：段间有累计状态（前段结果参与后段）时，独立分段复算不成立
- 证据：strong ｜ 3源(52pj3) ｜ 2019–2025 ｜ 命中69
- 锚点：848363,2068987,1952584

<a id="win-017"></a>
#### win-017 用单变量对照实验分自校验：内容、签名、路径
- 症状：改完能启动过一会失效；重新签名就被拦
- 判断：只改内容正常→不验内容；只重签名异常→验签名；断网仍异常→本地验签名
- 动作：固定其余变量每次只改一项看谁触发；内容校验断哈希链，签名校验断 WinVerifyTrust 返回值
- 无效则：两种改法都异常 → 还有路径/文件大小附带校验，再单独试改路径与大小
- 失效条件：校验结果只用于延时降级（不报错只减功能）时，对照实验在现象层不显现
- 证据：strong ｜ 5源(52pj5) ｜ 2011–2024 ｜ 命中8
- 锚点：308724,146886,674877,107147,1885129

## 阶段：补丁

<a id="win-018"></a>
#### win-018 改 caller 的判定分支，不改 crc32/md5 这类 callee
- 症状：改了校验函数别处崩；改了没效果
- 判断：纯计算函数被多处复用 → 改它牵连其他逻辑，判定只在调用点
- 动作：回调用点看哪条分支只影响目标行为，只改那一条
- 无效则：调用点太多无法逐个改 → 用内存 hook 在调用点过滤，不动函数体
- 失效条件：判定逻辑内联进 callee 且只有唯一调用时，改 caller 反而不如改 callee 省
- 证据：strong ｜ 4源(52pj4) ｜ 2012–2024 ｜ 命中4
- 锚点：1885129,488148,146886,1538587

<a id="win-019"></a>
#### win-019 跳过校验优于把比较结果改成相等
- 症状：改成立刻被别处发现；改了结果引出副作用
- 判断：改结果会留下被后续逻辑读取的状态 → 控制流跳过不产生副作用
- 动作：x86 上把 jz/jnz（74/75）改 jmp（EB）或 nop（90），只动一处
- 无效则：分支后有必须执行的初始化 → 不能整段跳，改条件寄存器初值
- 失效条件：代码有 CRC 自校验时，改字节本身即被检出，须配 win-017
- 证据：strong ｜ 4源(52pj4) ｜ 2014–2026 ｜ 命中10
- 锚点：531615,2002195,263211,2121326

<a id="win-020"></a>
#### win-020 风险排序：内存 hook 优于改磁盘文件，再优于重打包
- 症状：不知道改内存还是改文件；重打包后一堆功能坏
- 判断：落盘改动会被完整性校验抓且难回滚 → 能运行时改就先不动文件
- 动作：先用调试器内存 patch 验证效果，确认后再决定是否固化到文件
- 无效则：必须分发或离线生效 → 才落盘，且只固化已验证的一处
- 失效条件：目标在启动早期就对自身映像做哈希时，内存 patch 同样被抓
- 证据：strong ｜ 4源(52pj4) ｜ 2012–2026 ｜ 命中101
- 锚点：165217,257140,657040,2131256

<a id="win-021"></a>
#### win-021 dump 的 PE 先按节表回填 raw，再重建 IAT
- 症状：dump 出来 IDA 打不开；节表对不上文件大小
- 判断：内存 dump 是 VirtualSize 布局，与 FileAlignment 不同 → 当文件用缺节错位
- 动作：按 PointerToRawData 回填各节，再用 Scylla/imprec 重建导入表后存盘
- 无效则：IAT 全空但只用 GetProcAddress → 先验证能跑再决定
- 失效条件：壳运行时加密 IAT 并自行重建时，FirstThunk 不可用
- 证据：strong ｜ 4源(52pj4) ｜ 2010–2025 ｜ 命中9
- 锚点：310268,197136,42303,2044339

<a id="win-022"></a>
#### win-022 必改文件时只改一处判定，其余只用于观察
- 症状：一次改很多处对不上原因；定位不到是哪处生效
- 判断：多点同时改会丢失归因 → 只固化已验证生效的那一处
- 动作：先记全部观察点，最终只落盘一处判定分支的字节
- 无效则：单点改完仍不生效 → 回 win-017 判是否有第二层校验
- 失效条件：同一判定在多处展开且互相兜底时，单点改必被另一处还原
- 证据：strong ｜ 4源(52pj4) ｜ 2016–2026 ｜ 命中5
- 锚点：2121326,969755,674877,531615

<a id="win-023"></a>
#### win-023 .NET 改 IL 不改字节，用 dnSpy 或 dnlib 重写
- 症状：改 IL 字节后程序集加载失败；强命名 dll 改不了
- 判断：IL 与元数据表互相索引，手改字节易破坏元数据 → 用反编译级工具改
- 动作：dnSpy 直接改方法体保存；或 dnlib 脚本改写；强命名先解签名再重签
- 无效则：壳把 IL 加密 → 先 dump 出方法体（win-021）再改
- 失效条件：目标做了 IL 加密或方法体抽取、并用强命名加哈希校验时，原地改 IL 无效
- 证据：strong ｜ 5源(52pj5) ｜ 2009–2026 ｜ 命中17
- 锚点：289232,218529,280864,17719,2126348

<a id="win-024"></a>
#### win-024 VB6 先判 p-code 还是 native，再选工具
- 症状：VB 里全是看不懂的 call；反编译出来是伪代码
- 判断：导入 msvbvm60 且代码是解释器调用 → p-code；有正常 x86 过程 → native
- 动作：p-code 用 VB Decompiler 看事件与字符串；native 照常 IDA 读
- 无效则：两者混合 → 以字符串与事件表为锚点分别处理
- 失效条件：VB 程序加壳或运行时被重打包后，p-code 与 native 边界静态看不出
- 证据：strong ｜ 5源(52pj5) ｜ 2009–2019 ｜ 命中16
- 锚点：984487,943702,397135,992343,34772

<a id="win-025"></a>
#### win-025 Delphi 认 VCL 事件表与 RTTI，从控件事件定位校验
- 症状：Delphi 函数名看不懂；消息循环里找不到校验
- 判断：有 rtl/VCL 导入且窗口是 TForm → 控件事件挂在 DFM 资源里，比追消息快
- 动作：用 IDR 或 DeDe 还原窗体与事件地址，再在事件处下断反查校验
- 无效则：窗体资源被壳加密 → 先脱壳再还原事件表
- 失效条件：纯控制台或无窗体程序没有 DFM 事件表时此法不适用
- 证据：strong ｜ 5源(52pj5) ｜ 2010–2018 ｜ 命中17
- 锚点：237793,616743,686824,36976,774163

<a id="win-026"></a>
#### win-026 hook 不生效先查三因：重解析、模块未到、指令长度
- 症状：hook 装上了函数照常返回原值；注入成功但毫无效果
- 判断：无报错且行为不变 → 目标自己 GetProcAddress 重取地址、模块未映射或 inline 覆盖长度不足
- 动作：改 IAT 指针式 hook 规避长度问题；时机放到模块映射后，并每秒重试取址
- 无效则：仍无效 → 目标内联 syscall 或直调 ntdll，转内核层
- 失效条件：目标断言被 hook 槽位的原函数地址时，改指针即被检出
- 证据：strong ｜ 4源(52pj4) ｜ 2014–2017 ｜ 命中6
- 锚点：257140,657040,472730,352710

## 阶段：验证

<a id="win-027"></a>
#### win-027 位置一律记模块名加 RVA，禁写死绝对地址
- 症状：换台机器偏移全废；脚本里的地址下次就不对
- 判断：PE 默认 DYNAMICBASE，每次基址随机但 RVA 恒定 → 绝对地址不可跨运行
- 动作：记 VA=基址+RVA；文件偏移=RVA-节.VirtualAddress+PointerToRawData
- 无效则：只有 VA 没有模块信息 → 先在模块列表反查所属模块再换算
- 失效条件：重定位表被壳抹掉或运行中自搬代码段时，RVA 也不稳定
- 证据：strong ｜ 4源(52pj4) ｜ 2009–2026 ｜ 命中8
- 锚点：17719,382872,41051,2110871

<a id="win-028"></a>
#### win-028 注册机必须多组不同输入复算，一组过不算
- 症状：算出的码本机能用换机不行；一组过了就交付
- 判断：一组命中可能是碰巧或有隐藏条件（遇某字符就 break）→ 多组才暴露
- 动作：用纯字母、大小写混合、含数字三组复算，再与原程序双向对拍
- 无效则：三组都不过 → 算法未还原对，回 win-015/016 重定位
- 失效条件：算法含时间或硬件相关输入时，静态复算与实测必然不同，需带同类输入对拍
- 证据：strong ｜ 4源(52pj4) ｜ 2009–2022 ｜ 命中23
- 锚点：19284,1624259,718643,377047

<a id="win-029"></a>
#### win-029 改完能跑或显示已注册不是证据，做前后对照
- 症状：标题显示已注册但功能还限制；跑一会静默退回原行为
- 判断：存在静默降级与伪破解（只改显示）→ 表面现象不反映判定是否真被改
- 动作：原始件与改动件跑同一路径做对照，核对功能面而非提示文案，并 diff 改动字节
- 无效则：无可比基线 → 用独立复算与回读验证，别用没报错验收
- 失效条件：延时降级与后台回写注册表时，短时间内对照两边都正常
- 证据：strong ｜ 4源(52pj4) ｜ 2010–2024 ｜ 命中4
- 锚点：72374,584705,488148,1885129
