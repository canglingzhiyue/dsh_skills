#### huanjing-031 Windows 上改 Linux 源码与 zip 同名条目会静默改错
- 症状：报头文件不存在但文件在；改的和以为改的不是同一个文件　报错：`No such file or directory`
- 判断：NTFS 大小写不敏感把变体合并成 xxx(1).h；zip 同名条目只留一个 → 改错对象且不报错
- 动作：Linux 源码一律在 Linux 下改；zip 在条目层操作；报错目录先 ls 找 (1) 与 .bak
- 无效则：只能在 Windows → 用 WSL 挂载改文件，不要解压改再打包
- 失效条件：目录启用区分大小写、或 zip 工具改严格条目操作后，前提变化
- 证据：weak ｜ 2源(52pj2) ｜ 2020–2021 ｜ 命中8
- 锚点：1181293,1354106

#### huanjing-018 判定环境改动成功只认硬判据
- 症状：改了但看不出有没有生效；工具说成功了
- 判断：工具返回成功、fastboot 不报错都不是判据 → 唯一判据是能读出来的产物或行为差异
- 动作：用 /proc/version、dmesg、Listening 行、/proc/self/maps 基线、包能否启动并反编译做判据，并留对照组
- 无效则：没有可读产物 → 造对照：干净环境同一操作比差异
- 失效条件：判据项本身受权限限制（如新系统 dmesg 需 root）时换等价可读判据
- 证据：strong ｜ 3源(52pj3) ｜ 2020–2023 ｜ 命中0
- 锚点：1766826,1222455,1476883

#### huanjing-026 刷机成功只认回读内核版本并先看三件套
- 症状：刷完 boot 但内核没变；fastboot 没报错就以为成了
- 判断：fastboot 不报错不是判据；刷前不看基带/内核/构建号就选 boot.img → 刷错直接变砖
- 动作：刷前记下基带、内核版本、构建号三件套，刷后回读 /proc/version 比对
- 无效则：回读没变 → 查是否 GKI 用错 --vendor_ramdisk 与 --ramdisk
- 失效条件：设备改 GKI 分区布局后，boot 合并方式与判据都要重查
- 证据：strong ｜ 3源(52pj2/kanxue1) ｜ 2023–2023 ｜ 命中6
- 锚点：1766826,1805684,279746

#### huanjing-027 环境是否可用要设备列表与界面双确认
- 症状：容器起来了但连不上设备；以为环境好了其实没通　报错：`offline`
- 判断：容器 Up 或服务进程在都不算通 → 要设备列表里有设备且界面能起
- 动作：adb connect 后 adb devices 看设备，再用 scrcpy 看界面；容器场景查网桥是否开启
- 无效则：设备在但界面不出 → 查渲染与驱动，别再怀疑 adb
- 失效条件：换掉具体工具（scrcpy→其它投屏）时命令变，双确认原则不变
- 证据：weak＋缺口 ｜ 3源(kanxue3) ｜ 2024–2025 ｜ 命中19
- 锚点：280380,285317,286592

#### huanjing-028 setprop 与配置改动必须回读验证
- 症状：setprop 执行了但功能没生效；升级后设置全丢
- 判断：setprop 不校验键名、权限不足也常不报错 → 返回值不可信；改安装目录里的配置会在升级时被覆盖
- 动作：设完 getprop 回读；配置放用户目录同名文件只写改动项，不动安装目录
- 无效则：回读值对但行为不对 → 查是否被别的组件覆盖或策略拦写
- 失效条件：属性被 user 构建或 SELinux 限制写入时，回读能过而行为仍不变
- 证据：weak＋缺口 ｜ 2源(52pj1/kanxue1) ｜ 2020–2020 ｜ 命中4
- 锚点：1282827,279665
