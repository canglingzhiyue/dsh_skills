#### aifuzhu-005 任务书里先写死技术栈与已排除的路线
- 症状：AI 选了条死路；路线越走越偏
- 判断：只给开放式目标 → AI 自选一条看似合理实则死路；写清框架与排除项 → 它按可行路径走
- 动作：任务书点名框架/网络栈/加固，并列出已验证不可行的路线
- 无效则：技术栈未知 → 先做指纹识别，再谈交给 AI
- 失效条件：模型能自行抓 trace 反推框架时，先验提示的必要性下降

#### aifuzhu-008 mock 里字段设空跑出的分支不是通用算法
- 症状：穷举盐怎么都不过；拼出的原文少一段
- 判断：mock 里 uid 设空/缺省 → 字节码走进与真实不同的分支，产物仍自洽 → 把这特例路径当通用算法必然全错
- 动作：mock 关键字段全填真实量级非空值，再和真实请求的中间值比对
- 无效则：拿不到真实值 → 换更早的明文版本包做对照
- 失效条件：该字段确实允许为空且服务端接受空值时，空值分支就是合法路径

#### aifuzhu-009 Proxy 兜底与 toPrimitive 会把盐变成 0
- 症状：sign 全错；盐像是空串或 0
- 判断：Proxy 对未知属性返回兜底对象、stub 的 Symbol.toPrimitive 返回 0 → 假对象拼进原文变「0」，错得查不出来
- 动作：只拦截明确的属性，未知属性抛异常；打印签名原文而不只打印最终结果
- 无效则：仍是假对象 → 换成真实引擎跑原 VM
- 失效条件：不走 Proxy、直接在真实 JS 引擎里跑原 VM 时，此坑不存在
- 证据：single＋缺口 ｜ 1源(52pj0/kanxue1) ｜ 2026–2026 ｜ 命中75

#### aifuzhu-010 别把已知 key 写进 mock 再让它「发现」
- 症状：AI 说还原出 key；结果和预期一模一样
- 判断：把 key 硬编码进 mock 的加密实现 → 它「揭示」的就是你喂的；用已知答案的 mock 自证会被当成逆向结论

- 失效条件：mock 完全不含答案、输入输出均来自真实流量时，不构成自证

#### aifuzhu-011 部分环节全对不等于整体快对

- 判断：AES 25/25 全对 → 容易把误差归因「还差一个值」；真因常是签名字段集合里少一个动态字段

#### aifuzhu-022 同层三次无进展或脚本过 200 行就换层
- 症状：脚本越写越长；数据还是不对
- 判断：同层反复加 hook、拿到的全是辅助接口 → 层级选错；200 行与连败 3 次是经验阈值
