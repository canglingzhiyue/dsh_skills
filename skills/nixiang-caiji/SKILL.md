# nixiang-caiji —— 采集与提炼

采集和提炼是**同一条流水线的上下游**（共用 schema、风控、目录规范、质检口径），所以合成一个技能；但**蒸馏是另一件事**，在 `nixiang-zhengliu`。

## 0. 跑法契约（新站点只填这五项）

```
站点名 / 列表页入口（版块页 + 导读页）/ 正文选择器或 DOM 路径 / 权限与风控说明 / 目标目录
```

目录规范（沿用两个既有语料库）：
```
<项目>\
  notes\<tid>-<标题>.md     8 节笔记（提炼产物）
  raw\
    list\      列表页原始 JSON
    threads\<tid>.json   正文原始存档（★必须含 images 字段与 markdown 全文）
  data\        all_threads.json / stats.json / experience_pool.json
  docs\handbook\   跨帖归纳的主题手册（喂 nixiang-zhengliu 的主素材）
  ego\         ego-browser 采集脚本，每轮一个 round-N.mjs
  scripts\     Python 管线（只用标准库）
```

## 1. 采集

| 要点 | 内容 |
|---|---|
| 浏览器 | `ego-browser`（写 `.mjs`，`ego-browser nodejs -e "await import('file:///...')"`），或按站点选 `camoufox-reverse` |
| 分轮 | 每轮一个 `round-N.mjs`，可断点续采；列表 → 打分 → 排期 → 正文，四段分开 |
| **★ 正文存档必须带图** | 抓正文时把 `images`（绝对 URL 列表）与完整 `markdown` 一起存。**只存纯文本会丢图片**，而大量帖子的关键判据在截图里 |
| **★ kanxue 的坑** | 加速乐 + 网易易盾是**验证窗口**机制，不是速率机制：手动过一次滑块后约 1 小时窗口内可 fast 档（12–18 秒/篇）；窗口一关，降速到 55–75 秒/篇仍 100% 被拦、隔 8 小时也不恢复。唯一可行路径是**再过一次滑块**。脚本要写成"摆滑块并交权给用户 → 用户说继续 → 才接管抓满窗口"两段式 |
| 52pojie | 相对宽松，`i.52pojie.cn` / `attach.52pojie.cn` 图床可直接取 |
| 反例 | 不要用"降速 + 冷却探测"绕风控——实测已被证伪，只会浪费时间 |

## 2. 提炼（8 节 schema，固定不变）

每篇笔记固定 8 节，**第 3、5、6 节是全部价值所在**：

```markdown
# <一句话说清这篇讲什么，带上根因/结论>
> 原帖：<URL>  ｜ 作者：<> ｜ 发布：<年-月-日> ｜ 版块：<>
> 主题：<正题列表> ｜ 难度：硬核|进阶|入门   ← 头部元数据必须有，下游全依赖它

## 1. 目标与难点     对象是什么 / 要解决什么 / 难点在哪
## 2. 环境与工具     设备、静态工具、动态工具、抓包（表格）
## 3. 关键思路（核心）  ★ 判断链：看到 X → 凭什么推断 Y → 所以选 Z；换过思路要写"先试A失败因为…改试B"
## 4. 操作要点       可复现的命令/参数/偏移，但**不要整段搬运原文**
## 5. 踩坑与排错     ★ 表格：现象 / 原因 / 解法
## 6. 可复用经验     ★ 祈使句，下次能直接照做
## 7. 遗留 / 未验证   作者自认没做完的必须写进来（这是证据等级的来源）
## 8. 原文关键片段   保留技术事实：类名、方法名、so 名、偏移、命令、版本号、错误码
```

标注约定：**【原文】**= 作者明确说的；**【推断】**= 提炼者推断；`见原帖图 N` = 信息在截图里。

### 什么该判 SKIP（不提炼）
工具发布 / 汉化绿化 / 悬赏求助 / 资讯 / 签到脚本 / 与逆向无关的网站源码 —— 实测两个库的 SKIP 比例在 15–20% 是**正常形态**，不是 bug。

## 3. 质检（不通过不许交给蒸馏）

```powershell
uv run --no-project python scripts\audit_library.py   # 章节完整性 / 有笔记无正文 / 错误页误判
uv run --no-project python scripts\build_index.py     # INDEX.md + stats.json
uv run --no-project python scripts\extract_experience.py  # experience_pool.json
```

必查三项：
1. **8 节完整**：第 1/6 节覆盖应≈100%，第 8 节可能少（部分帖子无代码片段）；
2. **有笔记必有正文**：0 例；
3. **正文为空的帖子**：必须单独统计并标记（实测 kanxue 有 424 篇 markdown 为空但笔记存在 —— 那是从 `bodyText` 产出的，**无代码块、无图**，交给蒸馏时要压证据等级）。

## 4. 交给下游

```
语料库 → nixiang-zhengliu（证据化 → 渲染 → 三闸门）→ nixiang-shu 树
```

**别在采集端做取舍判断**（哪条经验该留该删）——那是蒸馏的活。采集端只保证：结构完整、技术事实不丢、图片地址可回查。
