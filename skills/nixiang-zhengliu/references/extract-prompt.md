# 主题提炼提示词模板（给 subagent 用，可复用）

> 每个新主题照这个模板替换 `{{THEME}}` / `{{HANDBOOKS}}` 即可派发。
> 沉淀它的目的：将来 `nixiang-zhengliu` 技能要对新语料库自动跑，不能每轮由我手写提示词。

---

## 模板正文

你的任务：把两库的「{{THEME}}」主题手册，蒸馏成一份**规则草案 JSON**。这是「逆向技能树」的一个主题节点，请当作交付物来写。

### 一、你读的输入（只读，不要修改）

1. 规则格式规范（**必须严格遵守**）：`{{SCHEMA}}`
2. 主题手册（跨帖归纳产物，主要素材）：
{{HANDBOOKS}}
3. 需要查证细节时，可在两库笔记里按关键词 grep（只读）：`52pojie\notes\`（`<tid>-<标题>.md`）、`kanxue\notes\`（`<tid>.md`）。每篇 8 节：第 3 节「关键思路」=判断链，第 5 节「踩坑与排错」=现象/原因/解法，第 6 节「可复用经验」=祈使句。

### 二、产出

写一个文件：`{{OUT}}`（结构见 schema）。规矩：
- 规则 **20–40 条**；整份渲染 ≤12,000 字符，单条 ≤900 字符。
- 必备字段：`id`（`{{PREFIX}}-001` 递增）、`title`（≤40 字祈使句）、`domain`、`stage`、`symptom`、`error_patterns`、`judge`、`action`、`if_not`、`invalidate_when`、`keys`、`anchors`、`evidence_hint`、`img_dependent`。

### 三、内容取舍（蒸馏价值观，必须照做）

1. **只留方法，不留成品**：不写"改某 App 的某方法返回 true"这类针对具体产品的步骤；成品只留 tid 锚点。
2. **判"过时"的单位是每条经验，不是每篇帖子**。五类主动清理：①工具已死（停更/本机没有）→ 可改写成"为什么被淘汰 + 现在用什么"的替代型规则；②对抗已升级 → 改写成"版本判别 + 分流"；③被新工具/AI 替代 → 改写成新途径；④当年环境搭建的坑 → **不写成规则**；⑤不可复现（单机/专属偏移）→ **不写成规则**。
3. **判断链优先**：`judge` 必须写"看到 X → 凭什么推断 Y"。
4. **`invalidate_when` 必须具体**：写"壳版本 ≥3.x 后 StubApp 不再是入口"，不写"版本更新后可能失效"。
5. **证据等级照手册标注**：「多篇一致（≥3 篇）」→`strong`；「弱共识」→`weak`；「孤例，需实测」→`single`。
6. **图片依赖**：关键判据只能靠原帖截图确认时 `img_dependent: true`。

### 四、锚点纪律

- 只填**你实际见到**的 tid（手册引用或 grep 读到的），每条 1–6 个，**不许编造**。
- 填之前验证文件存在：`52pojie\notes\<tid>-*.md` 或 `kanxue\notes\<tid>.md` 至少一个存在。

### 五、纪律

- **禁止开浏览器、禁止联网、禁止修改语料库**。只读 + 只写那一个输出文件。
- 简体中文（字段名英文）。先设 `$env:UV_CACHE_DIR` 与 `$env:PYTHONIOENCODING='utf-8'` 再跑 python 自检。
- 自检三项并报告：①`json.load` 通过且 `len(rules)` 是多少；②14 个必填字段 0 缺失；③渲染总字符 ≤12,000、单条 ≤900。

### 六、回报（≤500 字）

规则条数、覆盖的 domain/stage、清理掉哪几类过时经验（各类几条）、`img_dependent: true` 几条、自检三项结果、
以及**最不可靠的三条规则**（哪几条最需实测，各一句理由）。
