## 冒烟 4 —— 失败即报错、绝不降级

| 场景 | 结果 |
|---|---|
| 路径不存在 | `exit=1`，报「找不到要删除的路径 —— 已中止，未删除任何东西」 |
| 多路径里混一个不存在的 | `exit=1`，**其余存在的路径也一个都没删**（先全解析后删） |
| `-HardDelete` 不给 `-Reason` | `exit=1`，目标文件仍在（未误删） |
| Python 侧 `hard_delete(reason="")` | 抛 `ValueError`，未执行删除 |
| `-HardDelete -Reason '…'` | 永久删除，输出「永久删除（豁免清单）…（不可还原）」 |

## 冒烟 5 —— 中文与编码

- `Remove-ToRecycleBin.ps1` 首三字节 = `239,187,191`（UTF-8 BOM ✅，规则 2 要求）。
- pwsh 的 stdout 本身是 UTF-8 字节（`中文` → `e4 b8 ad e6 96 87`），与删除逻辑无关。
- Windows 下 **Python 的 stdout 默认 cp936**，直接 `print` 中文在按 UTF-8 读日志的终端里会乱码：
  `recycle.py` 因此改用 `-Quiet` 调用（只依据退出码、自己构造返回值），CLI 入口在 `_main()` 里
  `sys.stdout.reconfigure(encoding="utf-8")`，实测中文输出正常。

## 修掉的缺陷（都是实测才暴露的）

1. **多路径参数传不进去**：`pwsh -File x.ps1 -Path 'a','b'` 的逗号数组会变成单个字符串 `"a,b"`；
   `-Path a -Path b` 又被 PowerShell 拒绝（"多次指定了参数 'Path'"）。
   → 参数改成 `ValueFromRemainingArguments`，**外部调用用位置参数**，会话内才用 `-Path a, b`；
   `recycle.py` 改用 `pwsh -Command` 在会话内以 `-Path @(...)` 数组调用。
2. **中文返回值解析**：`recycle.py` 原先解析 pwsh 的中文 stdout，改用 `-Quiet` + 自己构造返回值。
3. **`.venv` 基础解释器来自 anaconda**：`uv run` 默认会挑系统 Python（本机 = anaconda 3.12.7）。
   → 装托管 CPython 3.12.13 + 全局 `python-preference = "only-managed"`。

## 测试方法本身的坑（记下来，别再踩）

`Select-Object -First N` 取够对象后会**提前掐断管道并终止上游进程**：用它截 `uv add -v` 的输出时，
`uv add` 被中途杀掉，`uv.lock` 没写成、`$LASTEXITCODE` 也不可信（一度误判成"uv 不生成 uv.lock"）。
测副作用必须先 `$out = cmd 2>&1; $code = $LASTEXITCODE`，再对 `$out` 截取。
