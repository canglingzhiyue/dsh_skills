# Camoufox 逆向环境 · 使用说明

> 本机（Windows 10 Pro for Workstations 22H2 / 19045）上的 Camoufox + `camoufox-reverse-mcp` 逆向环境。
> 全部组件装在工作区内，**不污染 Anaconda base、不写全局 Python site-packages**。
> 本文件由安装当天的实测结果写成，未验证的内容会明确标注。

## 0. 一分钟上手

| 我想做什么 | 怎么做 |
|---|---|
| 检查环境是否正常 | 双击桌面 **「Camoufox 逆向控制台」**（或工作区里的 `camoufox.cmd`）→ 选 `[1]` |
| 登录一个有扫码/短信验证的站 | 控制台 → `[2]`（普通会话）或 `[3]`（持久 profile，含 IndexedDB） |
| 让 AI 帮我逆向某站 | 在 DSH 会话里直接说：「用 camoufox 打开 xxx.com，抓一下登录接口的签名参数」 |
| **首次装机 / MCP 报 JSON 解析错** | 控制台 → `[7]` **预热引擎缓存**（原因见 §6.1，必须做一次） |
| 忘了装了什么、装在哪 | 控制台 → `[4]` 安装信息速查 |

## 3. 日常操作

### 3.0 首次装机后必做：预热引擎

```powershell
D:\AI_python\camoufox\.venv\Scripts\python.exe D:\AI_python\camoufox\bin\warmup.py
```

它启动一次浏览器，把 Camoufox 的默认插件（uBlock Origin）下载并缓存好。
**不做这一步，第一次 `launch_browser` 会失败**——原因见 §6.1。
（缓存被清、升级 Camoufox、或 MCP 客户端开始报 JSON 解析错误时，再跑一次。）

### 3.1 环境自检

```powershell
D:\AI_python\camoufox\.venv\Scripts\python.exe D:\AI_python\camoufox\bin\check_env.py
```

检查依赖版本窗口（`playwright < 1.63`）、引擎缓存、active 浏览器、定制版是否存在、
`vendor/acorn.cjs`、已保存的登录态清单。

### 3.2 可视化登录（扫码 / 短信 / 密码）

`camoufox-reverse-mcp` **不支持持久 profile**，每次 `launch_browser` 都是一套全新随机指纹；
跨会话保留登录只有一条官方路径：**导出登录态 → 下次导入**。所以人工登录用控制台菜单：

- 菜单 `[2]` — 普通会话：弹出真实浏览器窗口 → 你完成登录 → 回车 →
  保存到 `states\<站点>.json`。
- 菜单 `[3]` — 持久 profile：登录态写进 `profiles\<站点>\`（连 **IndexedDB / service worker /
  缓存**都保留），适合"普通导出会掉登录"的站点；同时也会导出 `states\<站点>.json` 供 MCP 使用。

之后在 DSH 会话里让 MCP 复用（**每次 `launch_browser` 之后都要重新 import**）：

```
mcp__camoufox__launch_browser()
mcp__camoufox__import_state(state_path="D:\\AI_python\\camoufox\\states\\<站点>.json")
mcp__camoufox__navigate(url="https://目标站点/...")
```

**关掉浏览器前再导出一次**，否则滚动刷新的 token 会留在内存里丢掉。

### 3.3 在 DSH 里驱动（MCP 已接入）

工具名形如 `mcp__camoufox__<tool>`（共 39 个）。典型开场：

```
1) mcp__camoufox__check_environment()        ← 先自检，别看错版本
2) mcp__camoufox__launch_browser()           ← 有头/无头都可用（本机实测，见 §9）
3) mcp__camoufox__navigate(url="https://target.com")
4) mcp__camoufox__take_snapshot()            ← token 友好的页面结构
```

### 3.4 自检冒烟测试（怀疑环境坏了时）

```powershell
# 只握手 + 自检
.venv\Scripts\python.exe bin\mcp_smoke_test.py
# 再真实启动浏览器 + 打开 example.com + 快照
.venv\Scripts\python.exe bin\mcp_smoke_test.py --browser
# 用定制版引擎 + 引擎层追踪
.venv\Scripts\python.exe bin\mcp_smoke_test.py --browser --reverse
```

## 5. 典型工作流

### 5.1 签名参数逆向

```
launch_browser() → inject_hook_preset("xhr") → inject_hook_preset("crypto")
→ navigate(登录页) → （用登录态或人工登录）→ 触发带签名请求
→ list_network_requests(method="POST") → get_request_initiator(request_id=N)   ← 定位签名函数
→ search_code("sign") → hook_function("window.getSign", mode="trace", world="main", persistent=True)
→ reload() → get_trace_data("window.getSign", world="main")
```

### 5.2 JSVMP / 混淆脚本

```
launch_browser() → network_capture(action="start") → navigate(目标站)
→ list_network_requests(resource_type="script")        ← 找到 VMP 脚本
→ instrumentation(action="install", url_pattern="**/vmp*.js", mode="ast")
→ inject_hook_preset("cookie", persistent=True) → instrumentation(action="reload")
→ instrumentation(action="log", type_filter="tap_get")     ← VMP 读了哪些环境
→ instrumentation(action="log", type_filter="tap_method")  ← VMP 调了哪些 API
→ compare_env()
```

> 反爬类型决定路线：**签名型**（瑞数、AK `sensor_data`）用 `instrumentation(install)`，
> **禁用** `pre_inject_hooks` 与 `hook_jsvmp_interpreter(mode="proxy")`；
> **行为型**（TK JSVMP、极验 gt4）用 `hook_jsvmp_interpreter(mode="proxy")`；
> 纯混淆可自由组合。详见仓库 `docs/JSVMP_PLAYBOOK.md`。

### 5.3 引擎层属性追踪（77 点，强证据）

```
launch_browser(browser_version="whitenightshadow/152.0.4-beta.30-reverse.5", enable_trace=True)
→ trace_property_access(action="start")
→ navigate(目标页) → 触发 JSVMP
→ trace_property_access(action="stop", mode="summary", collect_values=True)
→ trace_property_access(action="query", mode="timeline", bucket_ms=500)
→ trace_property_access(action="query", mode="search", search_query="cookie")
```

用途：确定 JSVMP 究竟读了哪些 Gecko 原生 API（Cookie/Canvas/WebGL/localStorage…），
据此在 Node.js 里补齐环境。**未命中不能证明未被读取**（只有构建声明的 77 个固定注入点有强证据）。
开启 tracing 时会临时关闭 content sandbox，只用于短时分析会话。

## 6. 已知限制与坑

### 6.1 `launch_browser` 首次失败：插件下载污染 stdout（**本机实测踩到过**）

Camoufox 首次启动会下载默认插件（uBlock Origin），进度直接打到 stdout：

```
\rDownloading addon (UBO)...\rExtracting addon (UBO): Complete\r
```

MCP 的 stdio 通道上 stdout 就是 JSON-RPC 流，于是客户端报：

```
Failed to parse JSONRPC message from server ... Invalid JSON
```

**对策**：装机后先跑一次 §3.0 的预热（菜单 `[7]`）。插件缓存后不再打印，问题消失。
若 MCP 客户端某天又开始报这个错，重跑预热即可。

### 6.2 其他限制

1. **每次 `launch_browser` 指纹都是新的**（BrowserForge 随机），MCP 无法固定。
   同一份 cookie 换一套指纹，更容易被要求二次验证——这是"无人值守复用"最大的不确定性。
2. **`export_state` / `import_state` 只覆盖 cookies + localStorage**，不含
   IndexedDB / OPFS / sessionStorage；且**没有自动加载**，每次 launch 后要手动 import。
   掉登录就改用菜单 `[3]` 的持久 profile。
3. **`take_screenshot` 返回 base64 文本**（本机实测约 18–19 KB 字符）而不是图像块，
   模型不一定"看得见"。要肉眼确认页面，直接看 Windows 桌面上那个真实窗口。
4. **`import_state` 每次新建 context**（`imported_1/2/…` 会累积），且不补 launch 时的字体回退脚本。
5. **不要在浏览器运行期间清理 trace 目录**（Windows 文件锁会让旧事件混入）。
6. **`playwright` 不要升到 1.63+**：camoufox 的 `pyproject` 上界是 `<1.63`
   （`camoufox.server` 用了 Playwright 私有 API）。也不要单独跑 `playwright install`。
7. **GitHub API 未认证限流 60 次/小时**：`camoufox fetch` 的频道同步会 403。
   装引擎请用 `bin\install-camoufox-browser.py`（直连 release CDN，不查 API）。
8. **引擎缓存目录不要手工塞东西**：`camoufox_path()` 在目录非空但缺 `.0.5_FLAG` 时会
   `rmtree` 整个缓存（上游行为）。

## 7. 故障排查

| 症状 | 处理 |
|---|---|
| MCP 报 `Failed to parse JSONRPC message` / `Invalid JSON` | 跑菜单 `[7]` 预热引擎（§6.1） |
| DSH 里看不到 `mcp__camoufox__*` | 确认 `~\.dsh\profiles\web\cordis.patch.yml` 含 `mcp-camoufox-reverse`（本机已配好）；profile 是 `patchReload: live`，改完等几秒或重启 DSH |
| `launch_browser` 报找不到浏览器 | 跑菜单 `[1]` 自检；必要时用 `bin\install-camoufox-browser.py` 重装引擎 |
| 浏览器进程残留 / 卡死 | `Get-Process camoufox | Stop-Process -Force` |
| 控制台中文乱码 | 已默认 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`；自建终端时也设上 |
| MCP 调用超时 | `cordis.patch.yml` 里 `toolCallTimeoutMs: 120000`（默认 60s），大页面可再调高 |
| 想验证链路是否完好 | `bin\mcp_smoke_test.py --browser`（本机已通过，见 §9） |

## 8. 重建 / 升级 / 卸载

### 重建环境（换机器或误删后）

```powershell
cd D:\AI_python\camoufox
# 1) 独立解释器 + 虚拟环境（uv；没有 uv 就用系统 Python 3.12 建 venv）
uv venv --python 3.12 --python-preference only-managed .venv
.\.venv\Scripts\python.exe -m ensurepip --upgrade
# 2) 引擎封装
.\.venv\Scripts\python.exe -m pip install -U "camoufox[geoip]"
# 3) 源码 + MCP
git clone https://github.com/WhiteNightShadow/camoufox-reverse-mcp.git
.\.venv\Scripts\python.exe -m pip install -e .\camoufox-reverse-mcp
# 4) 官方引擎（绕开 GitHub API 限流；版本/资产/sha256 变了要同步改）
.\.venv\Scripts\python.exe .\bin\install-camoufox-browser.py `
    v152.0.4-beta.30 camoufox-152.0.4-beta.30-win.x86_64.zip `
    ea52a02fb1cfb1813ef6a326bea03fb2b650c9774143d953a94a27bfc8f10072
# 5) 定制版：先从 release 下载 zip + SHA256SUMS + install-camoufox-reverse.py
#    https://github.com/WhiteNightShadow/camoufox-reverse/releases
.\.venv\Scripts\python.exe .\install-camoufox-reverse.py `
    .\camoufox-152.0.4-beta.30-win.x86_64.zip `
    --sha256 d73704543a759a224371a8f3019f02ffa3a96fb446b25b7a856f5203b8e2153b
# 6) 预热 + 验证
.\.venv\Scripts\python.exe .\bin\warmup.py
.\.venv\Scripts\python.exe .\bin\mcp_smoke_test.py --browser
```

> 安装时如果 `%LOCALAPPDATA%\camoufox` 还不是联接，先建目录联接：
> `New-Item -ItemType Junction -Path "$env:LOCALAPPDATA\camoufox" -Target "D:\AI_python\camoufox\.engine\camoufox"`

### 升级 MCP

```powershell
cd D:\AI_python\camoufox\camoufox-reverse-mcp
git pull
D:\AI_python\camoufox\.venv\Scripts\python.exe -m pip install -e .
```

### 升级引擎

见「重建环境」第 4–5 步；tag / 资产名 / sha256 可从 release 页或 GitHub API 的
`assets[].digest` 取得。

### 卸载

```powershell
Remove-Item -Recurse -Force C:\Users\y\AppData\Local\camoufox   # 删联接（D 盘数据仍在）
Remove-Item -Recurse -Force D:\AI_python\camoufox               # 删全部（**含登录态，先备份 states\**）
# 并删掉 ~\.dsh\profiles\web\cordis.patch.yml 里的 mcp-camoufox-reverse 条目
```
